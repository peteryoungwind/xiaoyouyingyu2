# 会员套餐与微信小程序支付需求规格

> 版本：1.0 | 最后更新：2026-06-27 | 状态：定稿
> 关联：在现有会员/卡密体系基础上，新增「会员套餐 + 微信小程序支付」开通方式。

---

## 1. 项目概述

- 产品类型：小柚英语现有会员体系增强。
- 一句话目标：保留卡密兑换会员，同时支持用户在微信小程序内选择会员套餐并通过微信支付开通或续费会员。
- 目标用户：小程序用户、会员用户、管理员。
- 主要场景：用户在小程序内选择套餐并支付，支付成功后自动获得会员权益；管理员在 PC 后台配置套餐、查看订单、手动开通或延长会员。
- 平台：
  - 用户端：微信小程序。
  - 管理端：现有 PC 后台。
  - 后端：现有 Spring Boot REST API。
- 成功定义：
  - 用户支付成功后会员状态立即生效。
  - 已有会员再次购买时在原到期时间上顺延。
  - 管理员可管理套餐、查看订单、查看用户会员到期时间、手动调整会员。
  - 现有卡密兑换流程保持可用。

---

## 2. 目标与非目标

### 目标

- 新增会员套餐管理能力，支持金额、时长、永久会员、限时折扣、上下架。
- 新增微信小程序内支付开通会员能力。
- 新增会员订单管理能力，管理员可查看订单和支付状态。
- 新增管理员手动开通、延长、设置永久会员能力。
- 统一支付、卡密、管理员手动开通后的会员有效期计算规则。
- 会员权限仅在权限判断时动态判断有效期，不通过定时任务降级用户角色。

### 非目标

- 不做 PC 网页支付、H5 支付、公众号 JSAPI 支付、Native 扫码支付。
- 不做自动退款、发票、优惠券、分销返佣、自动订阅续费。
- 不重做现有卡密后台功能；卡密生成、批量导入、导出、作废、使用记录保持现状。
- 不改变现有小程序会员状态展示位置和整体样式；只在购买会员流程需要处新增套餐和支付页面。
- 不要求定时修改 `users.role` 来处理会员过期。

## 3. 用户与角色

### 普通用户 `USER`

- 可查看自己的会员状态。
- 可通过现有卡密兑换会员。
- 可在小程序内选择会员套餐并发起微信支付。
- 支付成功或兑换成功后，可访问会员功能。

### 会员用户

- 会员身份由动态权限判断得出：
  - `membership_permanent = true`，或
  - `membership_expire_at > now()`。
- 会员可继续购买套餐。
- 再次购买普通时长套餐时，在当前有效到期时间上顺延。
- 购买永久会员后永久有效。

### 管理员 `ADMIN`

- 始终拥有管理员权限和会员权限。
- 可管理会员套餐。
- 可查看会员订单列表、订单详情和支付状态。
- 可查看用户会员到期时间。
- 可手动开通、延长、设置永久会员或设置指定到期时间。
- 可继续使用现有卡密管理能力。

- FR-4 微信支付回调与会员开通。

- FR-6 管理员订单管理。
- FR-7 管理员手动开通和延长会员。
- FR-8 动态会员权限判断。
- FR-9 现有卡密流程兼容统一会员开通逻辑。
- FR-10 微信支付接入资料准备与配置。

### Later / 可选

- 自动退款和退款状态同步。

- 不要求用户角色到期后自动从 `PREMIUM_USER` 改回 `USER`。

## 5. 核心业务规则

### BR-1 会员有效期顺延

- 用户无会员、会员已过期时，购买普通时长套餐后：
  - 新到期时间 = 支付成功时间 + 套餐时长。
- 用户当前会员未过期时，购买普通时长套餐后：
  - 新到期时间 = 当前会员到期时间 + 套餐时长。
- 用户购买永久会员后：
  - `membership_permanent = true`。
  - `membership_expire_at` 可为空，或保留历史到期时间但不参与权限判断。
- 永久会员再次购买普通时长套餐时：
  - 不改变永久会员状态。
  - 可记录订单和会员变更记录，但不缩短、不覆盖永久会员。
- 管理员手动延长会员默认遵循同样顺延规则。
- 管理员手动设置指定到期时间时，以管理员选择的时间为准。

### BR-2 会员权限动态判断

- 后端权限判断必须使用统一方法，例如 `MembershipService.isActiveMember(user)`。
- 判断规则：
  - `ADMIN`：永远拥有会员权限。
  - 非管理员：`membership_permanent = true` 或 `membership_expire_at > now()`。
- `users.role` 不作为会员是否有效的唯一依据。
- 会员过期后不需要定时降级角色；用户再次访问会员接口时由动态权限判断拦截。
- 登录响应、用户信息接口、小程序全局状态应返回 `membershipActive`、`membershipExpireAt`、`membershipPermanent`。

### BR-3 套餐上下架

- 只有上架套餐在小程序端展示。
- 下架套餐不可新购。
- 已创建订单必须保存套餐快照，不受后续套餐编辑影响。
- 套餐删除建议采用软删除或下架，不建议物理删除。

### BR-4 价格与折扣

- 金额必须以整数分存储和计算。
- 套餐支持：
  - 原价 `original_price_cents`。
  - 现价 `sale_price_cents`。
  - 限时折扣开始时间 `discount_start_at`。
  - 限时折扣结束时间 `discount_end_at`。
- 创建订单时，实际支付金额以当时可购买价格为准，并写入订单快照。
- 若配置了限时折扣，只有当前时间在折扣区间内时才按折扣价创建订单。
- 若折扣已过期，小程序端应刷新套餐后再下单。

### BR-5 订单状态

订单状态：

- `PENDING`：待支付。
- `PAID`：已支付。
- `CLOSED`：超时关闭或用户未完成支付后关闭。
- `FAILED`：创建微信支付单失败或支付异常。
- `REFUNDED`：预留状态，V1 不实现自动退款。

状态规则：

- 订单创建后 15 分钟未支付，系统自动关闭。
- 已关闭订单不可继续支付。
- 微信支付回调必须幂等处理。
- 同一微信支付交易号只能开通一次会员。
- 支付成功但会员开通失败时，订单应保留异常原因，管理员可补偿处理。

## 6. 核心用户流程

### Flow 1：小程序购买会员

- 入口：现有会员入口、学习中心会员拦截提示、个人中心会员状态区域。
- 步骤：
  1. 用户进入会员购买页。
  2. 系统展示当前会员状态和上架套餐。
  3. 用户选择套餐并点击开通。
  4. 后端创建会员订单并调用微信支付 JSAPI/小程序下单。
  5. 后端返回 `wx.requestPayment` 所需参数。
  6. 小程序调用 `wx.requestPayment`。
  7. 用户完成支付。
  8. 微信支付回调通知后端。
  9. 后端校验回调、更新订单、开通或顺延会员。
  10. 小程序查询订单或会员状态并刷新页面。
- 成功：用户会员状态变为有效，或到期时间顺延。
- 异常：
  - 用户取消支付：订单保持 `PENDING`，15 分钟后关闭。
  - 支付参数创建失败：订单标记 `FAILED`，提示用户稍后重试。
  - 回调延迟：前端支付成功后轮询订单状态，未确认时展示“支付确认中”。

### Flow 2：管理员配置套餐

- 入口：PC 后台会员套餐管理。
- 步骤：
  1. 管理员新增套餐。
  2. 填写名称、原价、现价、时长或永久、折扣时间、排序、状态。
  3. 保存后上架。
  4. 小程序端展示该套餐。
- 成功：上架套餐可被用户购买。
- 异常：金额、时长、折扣时间非法时保存失败并提示具体原因。

### Flow 3：管理员查看订单与手动处理会员

- 入口：PC 后台订单管理、用户管理。
- 步骤：
  1. 管理员查看订单列表。
  2. 按状态、用户、时间范围筛选。
  3. 查看订单详情和会员开通结果。
  4. 如需补偿，进入用户管理手动延长或设置会员。
- 成功：订单和会员变更记录可追溯。
- 异常：普通用户访问后台接口返回 403。

## 7. 功能需求

### FR-1 会员套餐管理

- 目标：管理员可在 PC 后台维护会员套餐。
- 输入字段：
  - 套餐名称，必填。
  - 套餐描述，可选。
  - 原价，必填，单位元，后端存分。
  - 现价，必填，单位元，后端存分。
  - 套餐类型：普通时长 / 永久会员。
  - 时长天数：普通时长套餐必填。
  - 折扣开始时间，可选。
  - 折扣结束时间，可选。
  - 排序值，可选，默认 0。
  - 状态：上架 / 下架。
- 输出：套餐列表和套餐详情。
- 权限：仅管理员。
- 边界：
  - 现价不能小于 0。
  - 原价不能小于现价，若业务允许特价高于原价则需明确提示。
  - 普通时长套餐 `duration_days > 0`。
  - 永久会员套餐不需要 `duration_days`。
  - 折扣结束时间必须晚于折扣开始时间。

验收：

- [ ] 管理员可新增、编辑、上架、下架套餐。
- [ ] 下架套餐不在小程序展示。
- [ ] 编辑套餐不影响历史订单快照。
- [ ] 非法金额、非法时长、非法折扣时间无法保存。

### FR-2 小程序套餐展示与购买入口

- 目标：用户可在小程序内选择会员套餐。
- 展示内容：
  - 当前会员状态：未开通 / 有效期至某日期 / 永久会员。
  - 套餐名称、描述、时长、原价、现价、折扣标签。
  - 开通按钮。
- 权限：
  - 未登录用户点击购买时跳转登录。
  - 登录用户可创建订单。
- 状态：
  - Loading：加载套餐中。
  - Empty：暂无可购买套餐。
  - Error：加载失败，可重试。
  - Paying：创建订单和调起支付期间禁用按钮。

验收：

- [ ] 小程序只展示上架套餐。
- [ ] 未登录用户不能创建订单。
- [ ] 点击购买后可以调起微信支付。
- [ ] 支付完成后刷新会员状态。

### FR-3 创建微信支付订单

- 目标：后端为用户创建会员订单并返回小程序支付参数。
- 触发：小程序调用创建订单接口。
- 输入：
  - `planId`。
  - 当前登录用户。
  - 用户微信 `openid`。
- 输出：
  - 业务订单号 `orderNo`。
  - 订单过期时间 `expiresAt`。
  - 小程序支付参数：`timeStamp`、`nonceStr`、`package`、`signType`、`paySign`。
- 业务规则：
  - 订单有效期 15 分钟。
  - 后端调用微信支付 API v3 JSAPI/小程序下单接口。
  - `description` 使用可识别商品描述，例如 `小柚英语会员-月度会员`。
  - `out_trade_no` 使用系统唯一订单号。
  - `amount.total` 使用订单金额，单位分。
  - `payer.openid` 使用当前小程序用户的 openid。
  - `notify_url` 使用公网 HTTPS 回调地址。

验收：

- [ ] 已下架套餐不能创建订单。
- [ ] 没有 openid 的用户不能创建微信支付订单，并提示重新微信登录。
- [ ] 创建成功后数据库有 `PENDING` 订单。
- [ ] 返回参数可直接传入 `wx.requestPayment`。

### FR-4 微信支付回调与会员开通

- 目标：支付成功后自动开通或顺延会员。
- 触发：微信支付回调 `notify_url`。
- 输入：
  - 微信支付通知报文。
  - 微信支付签名头。
- 输出：
  - 微信要求的成功/失败响应。
  - 更新后的订单和会员记录。
- 业务规则：
  - 回调接口不需要 JWT，但必须校验微信支付签名。
  - 必须解密回调资源数据。
  - 必须校验订单号、金额、商户号、支付状态。
  - 回调处理必须幂等。
  - 支付成功后，在同一事务内更新订单、写入会员记录、更新用户会员字段。

验收：

- [ ] 重复回调不会重复延长会员。
- [ ] 金额不一致时拒绝开通并记录异常。
- [ ] 订单不存在时记录异常并返回失败。
- [ ] 支付成功后订单变为 `PAID`，用户会员状态变为有效。

### FR-5 订单超时关闭

- 目标：15 分钟未支付订单自动失效。
- 触发：
  - 定时任务每分钟扫描。
  - 或用户再次进入订单详情时顺带检查。
- 业务规则：
  - `PENDING` 且 `expires_at <= now()` 的订单改为 `CLOSED`。
  - 已支付订单不能被关闭。
  - 若微信侧已支付但本地仍是 `PENDING`，应先主动查询微信订单状态，再决定是否关闭。

验收：

- [ ] 待支付订单超过 15 分钟后变为 `CLOSED`。
- [ ] 关闭订单不可再次发起支付。
- [ ] 已支付订单不会被超时任务关闭。

### FR-6 管理员订单管理

- 目标：管理员可查看支付订单和会员开通结果。
- 查询条件：
  - 用户名或用户 ID。
  - 订单号。
  - 订单状态。
  - 创建时间范围。
  - 支付时间范围。
- 列表字段：
  - 订单号。
  - 用户。
  - 套餐名称。
  - 支付金额。
  - 状态。
  - 微信交易号。
  - 创建时间。
  - 支付时间。
  - 会员开通状态。
- 详情字段：
  - 套餐快照。
  - 微信支付参数摘要。
  - 回调时间。
  - 失败原因。
  - 关联会员记录。

验收：

- [ ] 管理员可分页查看订单。
- [ ] 支持按状态和时间筛选。
- [ ] 订单详情能看到套餐快照和会员开通结果。
- [ ] 非管理员访问返回 403。

### FR-7 管理员手动开通和延长会员

- 目标：管理员可对指定用户进行会员补偿或人工开通。
- 操作类型：
  - 延长指定天数。
  - 设置为永久会员。
  - 设置指定到期时间。
  - 取消永久会员并设置到期时间。
- 必填信息：
  - 操作原因。
- 业务规则：
  - 延长指定天数默认使用顺延规则。
  - 设置指定到期时间直接覆盖 `membership_expire_at`。
  - 设置永久会员将 `membership_permanent` 置为 true。
  - 操作必须写入会员变更记录。

验收：

- [ ] 用户列表展示会员状态和到期时间。
- [ ] 管理员可延长会员并看到新到期时间。
- [ ] 管理员可设置永久会员。
- [ ] 每次手动操作都写入记录，包含操作人和原因。

### FR-8 动态会员权限判断

- 目标：会员权限由会员有效期动态判断，避免过期后仍能访问会员功能。
- 后端要求：
  - 新增或统一 `MembershipService.isActiveMember(User user)`。
  - 学习中心、AI 对话、会员内容接口使用该方法判断。
  - JWT 中的 `role` 不能单独决定会员是否有效。
- 前端要求：
  - 登录响应和用户信息接口使用后端返回的 `membershipActive`。
  - 小程序 `app.globalData.membershipActive` 来自后端，不在本地自行计算作为最终权限依据。

验收：

- [ ] 会员过期后访问会员接口返回 403 或统一会员到期错误。
- [ ] 管理员始终可访问会员功能。
- [ ] 修改系统时间或数据库到期时间后，权限判断即时生效。

### FR-9 现有卡密流程兼容

- 目标：保留现有卡密兑换，并复用统一会员开通逻辑。
- 已确认：当前卡密系统已有后台生成、批量导入、导出、作废、查看使用记录，并已有会员有效期相关能力。
- 要求：
  - 卡密兑换成功后调用统一会员授予方法，例如 `grantMembership()`。
  - 卡密兑换写入 `membership_records`，来源为 `REDEEM_CODE`。
  - 卡密兑换后的会员状态与支付开通一致。

验收：

- [ ] 原有卡密兑换流程不回归。
- [ ] 卡密兑换成功后会员状态刷新。
- [ ] 卡密兑换记录和会员变更记录均可追溯。

### FR-10 微信支付资料准备与配置

- 目标：明确上线前需要准备的资料和系统配置方式。
- 详见第 11 节。

验收：

- [ ] 开发环境可使用配置开关关闭真实支付或使用微信沙箱/测试商户能力。

## 11. 微信支付接入资料准备与配置

### 11.1 你需要准备的资料

#### 微信小程序资料

- 小程序 `AppID`。
- 小程序 `AppSecret`，若现有微信登录已配置，可复用。
- 小程序已认证，并具备可接入微信支付的主体条件。
- 小程序用户登录后，后端能拿到并保存当前用户的 `openid`。

#### 微信支付商户资料

- 微信支付商户号 `mchid`。
- 商户号已与小程序 AppID 完成绑定或授权关联。
- 已开通 JSAPI/小程序支付能力。
- 微信支付 API v3 密钥 `apiV3Key`。
- 商户 API 证书：
  - 商户私钥文件，例如 `apiclient_key.pem`。
  - 商户证书序列号 `merchantSerialNo`。
  - 商户证书文件如实现库需要使用，也一并准备。
- 微信支付平台证书：
  - 可由 SDK 自动下载并缓存，或人工配置平台证书。
  - 用于验签微信支付回调。

#### 服务器与域名资料

- 生产 API 域名，必须 HTTPS，例如 `https://xiaoyou-ky.top`。
- 微信支付回调地址：
  - `https://xiaoyou-ky.top/api/payment/wechat/notify`。
- 后端服务器可被微信支付公网访问。
- 服务器时间需要准确，建议开启 NTP。
- 生产数据库已备份，支付上线前需能回滚数据库变更。

#### 业务配置资料

- 会员套餐名称、描述、原价、现价、时长、是否永久。
- 限时折扣开始和结束时间。
- 支付商品描述前缀，例如 `小柚英语会员`。
- 客服或管理员补偿操作规范。

### 11.2 微信平台配置步骤

1. 登录微信商户平台。
2. 确认商户号已完成主体认证。
3. 在商户平台中关联小程序 AppID。
4. 开通 JSAPI/小程序支付产品能力。
5. 设置 API v3 密钥。
6. 下载或生成商户 API 证书，保存私钥和证书序列号。
7. 配置支付结果通知地址：
   - `https://<生产域名>/api/payment/wechat/notify`。
8. 确认小程序后台的服务器域名已配置生产 API 域名。
9. 使用真实微信号在体验版或正式版小程序中完成一笔低金额测试订单。

### 11.3 后端配置方式

`application.yml` 建议只保留环境变量占位，不写真实密钥：

```yaml
app:
  wechat-pay:
    enabled: ${WECHAT_PAY_ENABLED:false}
    app-id: ${WECHAT_PAY_APP_ID:}
    mch-id: ${WECHAT_PAY_MCH_ID:}
    api-v3-key: ${WECHAT_PAY_API_V3_KEY:}
    merchant-serial-no: ${WECHAT_PAY_MERCHANT_SERIAL_NO:}
    merchant-private-key-path: ${WECHAT_PAY_MERCHANT_PRIVATE_KEY_PATH:}
    platform-certificate-path: ${WECHAT_PAY_PLATFORM_CERTIFICATE_PATH:}
    notify-url: ${WECHAT_PAY_NOTIFY_URL:}
    order-expire-minutes: ${WECHAT_PAY_ORDER_EXPIRE_MINUTES:15}
```

生产环境变量示例：

```bash
export WECHAT_PAY_ENABLED=true
export WECHAT_PAY_APP_ID=wx_xxx
export WECHAT_PAY_MCH_ID=1900000001
export WECHAT_PAY_API_V3_KEY=your_api_v3_key
export WECHAT_PAY_MERCHANT_SERIAL_NO=your_certificate_serial_no
export WECHAT_PAY_MERCHANT_PRIVATE_KEY_PATH=/secure/wechat-pay/apiclient_key.pem
export WECHAT_PAY_PLATFORM_CERTIFICATE_PATH=/secure/wechat-pay/wechatpay_platform.pem
export WECHAT_PAY_NOTIFY_URL=https://xiaoyou-ky.top/api/payment/wechat/notify
export WECHAT_PAY_ORDER_EXPIRE_MINUTES=15
```

要求：

- `apiclient_key.pem` 不提交到 Git。
- 生产服务器上私钥文件权限建议设为仅应用运行用户可读。
- 日志不得打印 API v3 密钥、私钥、完整签名、用户 openid。
- 本地开发默认 `WECHAT_PAY_ENABLED=false`，避免误调真实支付。

### 11.4 小程序配置方式

- 小程序继续使用现有 `app.globalData.baseUrl`。
- 体验版和正式版必须指向 HTTPS API。
- 小程序端新增 API 方法：
  - `getMembershipPlans()`
  - `createMembershipOrder(planId)`
  - `getMembershipOrder(orderNo)`
  - `getMembershipStatus()`
- 小程序支付调用参数直接使用后端返回：

```js
wx.requestPayment({
  timeStamp: paymentParams.timeStamp,
  nonceStr: paymentParams.nonceStr,
  package: paymentParams.package,
  signType: paymentParams.signType,
  paySign: paymentParams.paySign,
  success() {
    // 查询订单状态或刷新会员状态
  },
  fail() {
    // 用户取消或支付失败，展示可重试提示
  }
})
```

注意：

- 小程序端不生成微信支付签名。
- 小程序端不保存商户密钥。
- 支付成功回调只代表客户端支付流程完成，最终会员开通以后端微信支付回调和订单查询结果为准。

### 11.5 开发、测试、生产建议

- 本地开发：
  - 使用 mock 支付开关或测试商户配置。
  - 后端可提供仅开发环境启用的模拟支付成功接口。
- 测试环境：
  - 使用体验版小程序。
  - 使用低金额测试套餐，例如 0.01 元。
  - 验证支付成功、取消支付、重复回调、超时关闭。
- 生产上线：
  - 上线前先下架所有真实套餐。

  - 测试成功后再上架正式套餐。
  - 保留支付日志和订单记录，便于对账。

## 12. 集成与外部服务

### 微信支付 API v3

- 用途：创建小程序支付订单、接收支付结果通知、必要时查询订单。
- 方向：
  - 后端 -> 微信支付：JSAPI/小程序下单、查询订单、关闭订单。
  - 微信支付 -> 后端：支付结果通知。
- 数据交换：
  - 下单：`appid`、`mchid`、`description`、`out_trade_no`、`notify_url`、`amount`、`payer.openid`。
  - 回调：交易状态、微信支付订单号、商户订单号、支付金额、支付时间。
- 认证：
  - 后端请求微信支付使用商户证书和 API v3 签名。
  - 回调使用微信支付平台证书验签。
- 失败处理：
  - 下单失败：订单标记 `FAILED`，前端提示稍后重试。
  - 回调验签失败：拒绝处理并记录安全日志。
  - 回调延迟：前端轮询订单状态；后端必要时主动查询微信订单。

官方参考：

- 微信支付 API v3 JSAPI/小程序支付文档：https://pay.weixin.qq.com/doc/v3/merchant/4012791856
- 微信小程序 `wx.requestPayment` 文档：https://developers.weixin.qq.com/miniprogram/dev/api/payment/wx.requestPayment.html

## 13. 技术约束

- 后端沿用 Spring Boot 3.2.5、Spring Security、Spring Data JPA、MySQL。
- PC 后台沿用 Next.js、React Query、Tailwind CSS。
- 小程序沿用 `xiaochengxu/miniprogram` 原生小程序结构和 `utils/request.js` 请求封装。
- 金额一律用整数分存储，接口展示时转换为元。
- 支付回调接口必须从 JWT 鉴权中放行，但不能跳过微信支付签名校验。
- 会员开通逻辑必须事务化。
- 订单号必须全局唯一，建议格式：业务前缀 + 时间 + 随机数。
- 数据库时间统一使用 `Asia/Shanghai` 业务展示，存储时保持项目现有约定。

## 14. 非功能需求

- 安全：
  - 密钥不得提交到代码仓库。
  - 回调必须验签。
  - 回调必须校验金额和商户订单号。
  - 管理员手动操作必须鉴权和记录。
- 可靠性：
  - 支付回调幂等。
  - 会员开通和订单更新在事务内完成。
  - 支付成功但开通失败时可人工补偿。
- 可观测性：
  - 记录下单、回调、验签失败、金额不一致、会员开通失败日志。
  - 管理后台可查看失败原因。
- 性能：
  - 套餐列表数据量小，可直接查询；如缓存，后台修改后必须及时失效。
  - 订单列表需要分页。
- 隐私：
  - 订单日志不展示敏感支付密钥。
  - 管理端可展示用户 ID 和用户名，不展示密码哈希。
