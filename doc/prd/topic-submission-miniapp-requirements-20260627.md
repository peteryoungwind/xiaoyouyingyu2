# 小程序用户提交话题需求方案

> 日期：2026-06-27  
> 适用项目：小柚英语 `xiaoyouyingyu2`  
> 参考原型：`prototype/topic-submission-entry/`

## 1. 项目概述

- **产品类型**：小柚英语小程序功能增强 + PC 管理后台功能增强
- **一句话目标**：允许已登录用户在小程序提交自己感兴趣的英语口语话题，管理员可在后台查看并标记处理结果。
- **目标用户**：
  - 小程序已登录用户：提交想练的话题。
  - 管理员：查看用户提交的话题并标记为已采纳或未采纳。
- **主要场景**：用户在首页轮播图或主题列表页看到提交入口，填写话题建议并提交；管理员在后台统一处理。
- **平台范围**：
  - 微信小程序
  - PC Web 管理后台
  - Spring Boot 后端 API
  - MySQL 数据库
- **成功定义**：
  - 已登录用户可以完成话题提交。
  - 未登录用户点击提交入口时被引导登录。
  - 管理员可以看到提交列表、查看详情、标记状态。
  - 提交成功后提示用户：如被采纳会出现在主题库。

## 2. 产品目标与非目标

### 2.1 目标

- 在小程序首页提供不突兀但可见的提交入口。
- 在主题列表页提供场景化辅助入口，承接“没有找到想练话题”的用户动机。
- 提供简洁的提交表单，降低用户提交门槛。
- 管理员后台可集中查看和处理提交话题。
- 为后续把高频用户需求转化为正式主题提供基础数据。

### 2.2 非目标

- V1 不提供“我的提交记录”页面。
- V1 不在管理员采纳后自动创建正式主题。
- V1 不向用户发送采纳通知。
- V1 不限制用户提交频率。
- V1 不做复杂去重、投票、点赞或评论功能。
- V1 不做匿名游客提交。

## 3. 用户与权限

### 3.1 小程序已登录用户

- 可以看到首页轮播图中的提交话题入口。
- 可以在主题列表页看到“没找到想练的话题”提交入口。
- 可以进入提交表单并提交话题。
- 不能查看自己的历史提交记录。
- 不能查看其他用户提交内容。

### 3.2 游客 / 未登录用户

- 可以看到提交入口。
- 点击提交入口后，应跳转登录页或弹出登录引导。
- 未登录状态下不能提交话题。

### 3.3 管理员

- 可以在 PC 管理后台查看用户提交话题列表。
- 可以查看提交详情。
- 可以将提交标记为“已采纳”。
- 可以将提交标记为“未采纳 / 忽略”。
- 可以看到提交人的用户名。
- V1 不需要自动创建正式主题。

## 5. 核心用户流程

### 5.1 用户从首页轮播提交话题

- **入口**：小程序首页顶部封面轮播第二张。
- **步骤**：
  1. 用户打开首页。
  2. 默认看到当前 Daily Practice 封面。
  3. 用户滑动或等待轮播到第二张“有想练的话题吗？”封面。
  4. 用户点击“提交话题”。
  5. 如果未登录，跳转登录页。
  6. 如果已登录，进入提交话题页面。
  7. 用户填写表单并提交。
  8. 页面提示“提交成功，如被采纳会出现在主题库”。
- **成功结果**：数据库新增一条 `PENDING` 状态的话题提交记录。
- **异常路径**：
  - 未登录：引导登录，登录后可重新进入提交页。
  - 网络失败：提示提交失败，可重试。
  - 必填字段为空：提示用户填写想练的话题。

### 5.2 用户从主题列表页提交话题

- **入口**：主题列表页搜索和标签筛选区域下方的辅助横幅。
- **步骤**：
  1. 用户进入主题列表页。
  2. 用户搜索或浏览主题。
  3. 页面展示“没有找到想练的话题？”横幅。
  4. 用户点击“提交”。
  5. 后续流程同首页入口。
- **成功结果**：数据库新增一条 `PENDING` 状态的话题提交记录。

### 5.3 管理员处理用户提交

- **入口**：PC 管理后台新增菜单“用户提交话题”。
- **步骤**：
  1. 管理员登录 PC 后台。
  2. 进入“用户提交话题”页面。
  3. 查看提交列表。
  4. 点击某条记录查看详情。
  5. 根据内容标记为“已采纳”或“未采纳”。
- **成功结果**：提交记录状态更新。
- **异常路径**：
  - 非管理员访问后台接口：返回 403。
  - 记录不存在：返回 404。
  - 重复更新状态：允许覆盖为新状态，更新 `updatedAt`。

## 6. 功能需求

### FR-1 首页封面轮播入口

- **目标**：在不额外占用首页空间的前提下增加提交话题入口。
- **触发**：用户进入小程序首页。
- **UI 要求**：
  - 只将首页当前封面区域改为轮播图，首页其它模块、顺序、数据展示保持不变。
  - 第一张为现有 Daily Practice 封面，默认展示。
  - 第二张为提交话题封面。
  - 第二张文案建议：
    - 标签：`Topic Wish`
    - 标题：`有想练的话题吗？`
    - 说明：`告诉小柚你的兴趣，我们会整理成适合开口练习的主题。`
    - 按钮：`提交话题`
  - 第二张视觉风格应与当前首页和谐，使用浅蓝、浅绿等柔和色，不做生硬广告式横幅。
  - 轮播应显示两个指示点。
  - 默认停留在第一张。
  - 轮播下方必须继续保留现有首页模块：
    - 四个学习入口：单词练习、AI 对话、每日外刊、跟读精听。
    - 三个统计卡片：主题总数、连续天数、热门标签。
    - 热门标签模块。
    - 最新主题模块。
    - 会员提示、底部提示等现有条件展示模块。
- **权限**：
  - 入口对所有用户可见。
  - 提交动作仅登录用户可用。
- **验收标准**：
  - [ ] 首页首屏封面变成两张轮播。
  - [ ] 打开首页时默认展示 Daily Practice。
  - [ ] 第二张点击“提交话题”可进入提交流程。
  - [ ] 未登录用户点击后进入登录引导。
  - [ ] 除顶部封面变为轮播外，首页其它模块保持原顺序和原展示逻辑。
  - [ ] 轮播不影响下方学习入口、统计卡片、热门标签和最新主题布局。

### FR-2 主题列表页辅助入口

- **目标**：在用户找不到合适话题时提供提交入口。
- **触发**：用户进入主题列表页。
- **UI 要求**：
  - 在搜索框、标签筛选区域下方展示辅助横幅。
  - 文案建议：
    - 标题：`没有找到想练的话题？`
    - 说明：`告诉我们你想聊什么，我们会优先整理高频需求。`
    - 按钮：`提交`
  - 横幅视觉权重低于主题列表主标题，高于普通列表项。
- **权限**：
  - 入口对所有用户可见。
  - 提交动作仅登录用户可用。
- **验收标准**：
  - [ ] 主题列表页可见提交入口。
  - [ ] 点击提交进入提交流程或登录引导。
  - [ ] 横幅不遮挡搜索、筛选和主题列表。

### FR-3 小程序提交话题页面

- **目标**：让已登录用户快速提交感兴趣的话题。
- **触发**：用户从首页轮播或主题列表页点击提交入口。
- **输入字段**：
  - `title`：话题标题 / 想练的话题，必填。
  - `reason`：为什么想练这个话题，选填。
  - `category`：分类标签，选填。
  - `extraInfo`：补充说明，选填。
- **字段建议文案**：
  - 标题 placeholder：`例如：面试时介绍自己的项目经历`
  - 原因 placeholder：`可以简单说说你为什么想练这个场景`
  - 补充说明 placeholder：`可填写目标水平、希望包含的问题、真实使用场景`
- **校验规则**：
  - `title` 必填，去除首尾空格后不能为空。
  - `title` 建议限制 2-100 个字符。
  - `reason` 建议限制 0-500 个字符。
  - `extraInfo` 建议限制 0-500 个字符。
- **状态**：
  - 默认态：显示表单。
  - 提交中：按钮 loading，不允许重复提交。
  - 成功态：提示“提交成功，如被采纳会出现在主题库”。
  - 失败态：显示失败原因，允许重试。
- **验收标准**：
  - [ ] 已登录用户可以提交表单。
  - [ ] 标题为空时不能提交。
  - [ ] 提交成功后展示指定成功文案。
  - [ ] 提交失败后不清空用户已填写内容。
  - [ ] 快速连续点击不会创建重复记录。

### FR-4 后端提交话题 API

- **目标**：提供小程序保存用户提交话题的接口。
- **建议接口**：
  - `POST /api/topic-submissions`
  - 权限：已登录用户
- **请求体**：

```json
{
  "title": "面试时介绍自己的项目经历",
  "reason": "最近准备英文面试，想练习怎么自然地讲项目背景、遇到的问题和自己的贡献。",
  "category": "职场",
  "extraInfo": "希望有初级和进阶两个版本。"
}
```

- **成功响应**：

```json
{
  "id": 1,
  "title": "面试时介绍自己的项目经历",
  "status": "PENDING",
  "createdAt": "2026-06-27T10:00:00"
}
```

- **失败响应**：
  - 未登录：401。
  - 参数错误：400，返回错误信息。
  - 服务异常：500，返回通用错误信息。
- **验收标准**：
  - [ ] 已登录用户提交后数据库产生记录。
  - [ ] 未登录请求返回 401。
  - [ ] 空标题返回 400。
  - [ ] 响应不泄露敏感用户信息。

### FR-5 管理后台提交列表

- **目标**：管理员可查看用户提交的话题。
- **入口**：PC 管理后台侧边栏新增“用户提交话题”。
- **列表字段**：
  - 话题标题
  - 提交用户名
  - 分类
  - 状态
  - 提交时间
  - 操作按钮
- **筛选建议**：
  - 状态筛选：全部、待处理、已采纳、未采纳。
  - 关键词搜索：按标题、原因、补充说明搜索。
- **分页**：
  - 默认每页 20 条。
  - 按提交时间倒序排列。
- **验收标准**：
  - [ ] 管理员可以看到提交列表。
  - [ ] 非管理员不能访问列表接口和页面。
  - [ ] 列表默认按 `createdAt` 倒序。
  - [ ] 列表中只显示用户名，不显示密码、token 或其它敏感信息。

### FR-6 管理后台提交详情

- **目标**：管理员可查看单条提交完整内容。
- **详情字段**：
  - 话题标题
  - 提交用户名
  - 分类
  - 想练原因
  - 补充说明
  - 当前状态
  - 提交时间
  - 更新时间
- **操作**：
  - 标记为已采纳
  - 标记为未采纳
- **验收标准**：
  - [ ] 管理员可以打开详情。
  - [ ] 详情展示完整提交内容。
  - [ ] 不存在的记录返回 404 或展示错误态。

### FR-7 管理后台状态更新

- **目标**：管理员可处理提交记录。
- **建议接口**：
  - `PUT /api/admin/topic-submissions/{id}/status`
  - 权限：管理员
- **请求体**：

```json
{
  "status": "ACCEPTED"
}
```

- **允许状态**：
  - `PENDING`：待处理
  - `ACCEPTED`：已采纳
  - `REJECTED`：未采纳 / 忽略
- **业务规则**：
  - 新提交默认状态为 `PENDING`。
  - 管理员可将任意状态更新为 `ACCEPTED` 或 `REJECTED`。
  - V1 不自动创建正式主题。
  - V1 不通知用户。
- **验收标准**：
  - [ ] 管理员可以把待处理记录标记为已采纳。
  - [ ] 管理员可以把待处理记录标记为未采纳。
  - [ ] 状态更新后列表和详情同步展示。
  - [ ] 非管理员请求返回 403。

## 7. 页面与 UI 要求

### 7.1 视觉方向

- 保持小柚英语现有小程序风格。
- 首页轮播第二张不做强广告感设计。
- 推荐颜色：
  - 第一张沿用现有浅蓝背景。
  - 第二张使用浅蓝到浅绿的柔和过渡或同等柔和色块。
- 组件风格：
  - 圆角与首页现有 hero 保持一致。
  - 按钮样式与现有蓝色主按钮一致，第二张可使用绿色或蓝绿色，但不得显得突兀。
  - 不新增复杂动效。

### 7.2 小程序首页

- **目的**：提供主要学习入口，同时通过轮播承载提交话题入口。
- **关键内容**：
  - 顶部封面轮播
  - 四个学习入口
  - 统计卡片：主题总数、连续天数、热门标签
  - 热门标签
  - 最新主题
- **主要动作**：
  - 第一张：去学习
  - 第二张：提交话题
- **加载态**：
  - 首页数据加载时不影响轮播静态展示。
- **错误态**：
  - 首页统计或主题加载失败时，轮播仍应可展示。

### 7.3 小程序主题列表页

- **目的**：浏览和搜索话题，并提供辅助提交入口。
- **关键内容**：
  - 标题
  - 搜索框
  - 标签筛选
  - 提交话题横幅
  - 主题列表
- **主要动作**：
  - 搜索
  - 标签筛选
  - 提交话题
  - 查看主题详情

### 7.4 小程序提交话题页

- **目的**：收集用户想练的话题。
- **关键内容**：
  - 表单标题
  - 必填标题输入框
  - 原因输入框
  - 分类选择
  - 补充说明输入框
  - 提交按钮
- **成功态**：
  - 显示“提交成功，如被采纳会出现在主题库”。
  - 提供“继续浏览主题”和“返回首页”两个动作。
- **错误态**：
  - 参数错误：在对应字段附近提示。
  - 网络错误：顶部或按钮附近提示，可重试。

### 7.5 PC 管理后台用户提交话题页

- **目的**：管理员集中处理用户提交的话题。
- **关键内容**：
  - 待处理数量
  - 列表
  - 状态筛选
  - 搜索
  - 详情查看
  - 状态操作
- **空状态**：
  - 文案：`暂无用户提交的话题`
- **错误态**：
  - 接口失败时显示错误提示和重试按钮。

## 8. 数据模型

### 8.1 `topic_submissions`

- **说明**：保存用户提交的话题建议。
- **建议字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BIGINT | 是 | 主键，自增 |
| `user_id` | BIGINT | 是 | 提交用户 ID |
| `username` | VARCHAR(50) | 是 | 提交时用户名快照 |
| `title` | VARCHAR(100) | 是 | 用户想练的话题 |
| `reason` | VARCHAR(500) / TEXT | 否 | 想练原因 |
| `category` | VARCHAR(50) | 否 | 分类 |
| `extra_info` | VARCHAR(500) / TEXT | 否 | 补充说明 |
| `status` | VARCHAR(20) | 是 | `PENDING` / `ACCEPTED` / `REJECTED` |
| `created_at` | DATETIME | 是 | 创建时间 |
| `updated_at` | DATETIME | 是 | 更新时间 |

- **关系**：
  - `topic_submissions.user_id` 关联 `users.id`。
  - 为方便后台展示，保留 `username` 快照。
- **索引建议**：
  - `idx_topic_submission_status_created_at(status, created_at)`
  - `idx_topic_submission_user_id(user_id)`

## 9. API 设计

### 9.1 用户提交话题

- `POST /api/topic-submissions`
- 权限：已登录用户
- 请求体：见 FR-4。
- 响应：创建后的简要提交记录。

### 9.2 管理员提交列表

- `GET /api/admin/topic-submissions`
- 权限：管理员
- 查询参数：
  - `page`：默认 0
  - `size`：默认 20
  - `status`：可选，`PENDING` / `ACCEPTED` / `REJECTED`
  - `keyword`：可选
- 响应：分页列表。

### 9.3 管理员提交详情

- `GET /api/admin/topic-submissions/{id}`
- 权限：管理员
- 响应：提交详情。

### 9.4 管理员更新状态

- `PUT /api/admin/topic-submissions/{id}/status`
- 权限：管理员
- 请求体：

```json
{
  "status": "ACCEPTED"
}
```

- **小程序**：复用现有 `xiaochengxu/miniprogram` 页面结构和样式体系。
- **PC 前端**：复用现有 Next.js 管理后台结构。
- **后端**：Spring Boot 3.2.5 + Spring Security + Spring Data JPA。
- **数据库**：MySQL。
- **认证**：
  - 小程序用户提交接口需要登录 token。
  - 管理后台接口需要 `ROLE_ADMIN`。
- **实现约束**：
  - 不引入新前端框架。
  - 不破坏现有首页学习入口。
  - 不改变现有话题表 `topics` 的含义。

## 11. 非功能需求

- **性能**：
  - 提交接口正常情况下 1 秒内返回。
  - 管理后台列表默认分页，避免一次加载全部数据。
- **安全**：
  - 用户提交接口必须校验登录态。
  - 后台接口必须校验管理员权限。
  - 列表和详情不得返回用户密码、token 等敏感信息。
- **可靠性**：
  - 提交失败不得清空表单。
  - 状态更新失败时不得修改前端本地状态为成功。
- **可维护性**：
  - 后端建议新增独立 Entity、Repository、Controller，不混入 TopicController。
  - 前端 API 封装应放入现有 API 客户端中。
- **可观测性**：
  - 后端记录提交创建和状态更新的基础日志。

## 13. 假设

- 现有小程序已有登录态和 token 请求封装，可直接复用。
- 现有 PC 管理后台已有管理员登录态和 API 请求封装。
- 分类标签使用简单字符串，不需要独立字典表。
- 管理员标记“已采纳”只表示人工处理状态，不会自动创建 `topics` 记录。
- 用户提交的话题属于平台内容运营参考数据，不需要对用户公开展示。

## 14. 开放问题

- 是否需要在后台显示“待处理数量”角标或仪表盘卡片？V1 可选。
- 是否需要管理员填写未采纳原因？V1 不做，后续可扩展。
- 是否需要在提交成功后推荐相近主题？原型中有类似方向，但 V1 可不做。
