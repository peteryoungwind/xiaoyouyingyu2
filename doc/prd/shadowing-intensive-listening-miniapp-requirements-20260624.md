## 1. 项目摘要

### 1.1 产品类型

在现有小柚英语微信小程序中，将“口语热身”学习入口替换为“跟读精听”。该模块基于固定的真实视频、音频和文本学习资料，而不是 AI 实时生成内容。用户通过视频/音频完成精听输入，通过逐句跟读和录音完成口语输出，再学习重点词汇、句型和地道表达。

### 1.2 一句话目标

让用户围绕真实英语视频/音频素材完成一次“听懂、读准、说出来、学表达”的移动端学习闭环。

### 1.3 目标用户

- 游客：可以查看跟读精听列表和详情页试看内容，只能看到媒体和简介。
- 登录用户：可以查看完整学习内容，逐句播放、录音、回放、提交 AI 点评和发音评分。
- 管理员：V1 不提供 PC 后台管理能力；开发阶段通过脚本批量导入资料。

### 1.4 平台范围

- 微信小程序：首页或学习模块入口、跟读精听列表页、跟读精听详情页。
- 后端服务：跟读精听资源接口、用户学习记录接口、句级录音点评接口、Markdown 导入脚本入口或命令。
- MySQL：新增跟读精听资源表、用户学习记录表、AI 点评记录表。
- AI 能力：复用现有 ASR 能力和默认 AI 模型进行综合评分，不接入专业发音评测服务。

### 1.5 成功定义

- 用户可以从小程序进入“跟读精听”。
- 游客可以浏览列表并试看媒体和简介。
- 登录用户可以查看完整内容，并在打开详情页时自动标记为已学习。
- 登录用户可以逐句播放、录音、回放并获得 AI 综合点评。
- 后续同类 Markdown 资料可以通过脚本批量导入为可学习资源。

## 2. 产品目标与非目标

### 2.1 目标

- 将现有“口语热身”用户入口替换为“跟读精听”。
- 建立未学习和已学习两个列表。
- 支持游客试看，试看范围仅包含媒体和简介。
- 支持登录用户查看完整视频、音频、文本、逐句跟读、重点表达和中文翻译练习。
- 支持每份资料独立配置视频链接和音频链接。
- 支持用户逐句录音、回放，并提交 AI 点评。
- 发音评分采用“现有 ASR + AI 综合评分”方案。
- 录音文件只用于临时处理，不长期保存。
- 保存识别文本、点评文本和评分结果，便于用户查看本次结果和后续数据分析。
- 支持开发阶段通过脚本批量导入 Markdown 资料。

### 2.2 非目标

- V1 不做 PC 管理后台。
- V1 不做音素级专业发音评测。
- V1 不接入第三方专业语音评测服务。
- V1 不长期保存用户录音文件。
- V1 不做学习时长统计、完成百分比、排行榜、打卡、收藏、点赞、评论和分享。
- V1 不要求游客查看完整文本、逐句内容、重点表达或 AI 点评。
- V1 不做资源爬取；只处理已经提供的 Markdown 或结构化资料。

## 3. 用户角色与权限

### 3.1 游客

- 可以进入跟读精听列表页。
- 可以查看资源卡片中的标题、中文标题、封面、简介、主题、栏目、日期、句子数和表达数。
- 可以打开详情页。
- 详情页只展示媒体区和简介。
- 不能查看对照原文、逐句跟读、地道表达和中文翻译练习。
- 点击受限内容或登录引导按钮时，进入现有登录流程。

### 3.2 登录用户

- 可以进入跟读精听列表页。
- 可以切换未学习和已学习列表。
- 可以查看完整详情页。
- 可以播放视频和音频。
- 可以查看对照原文、逐句跟读、地道表达和中文翻译练习。
- 可以逐句录音、回放、提交 AI 点评。
- 打开详情页后，该资源立即标记为已学习。

### 3.3 管理员

- 拥有登录用户在小程序端的全部学习能力。
- V1 不需要新增 PC 管理后台页面。
- 开发和运营阶段通过导入脚本批量导入资料。

## 4. V1 范围

### 4.1 V1 必须包含

- 小程序入口名称显示为“跟读精听”。
- 跟读精听列表页。
- 列表页支持 `未学习` 和 `已学习` 两个 tab。
- 游客可浏览列表。
- 游客打开详情页后，只展示媒体和简介。
- 登录用户打开详情页后，后端自动写入学习记录。
- 已打开过的资源出现在已学习列表，不再出现在未学习列表。
- 详情页顶部展示媒体区，支持视频和音频独立播放。
- 详情页展示资源简介。
- 详情页为登录用户展示对照原文、逐句跟读、地道表达、中文翻译练习，不再展示单独的“先听一遍”模块。
- 逐句跟读支持播放单句音频片段或根据时间轴播放媒体片段。
- 逐句跟读支持用户录音。
- 录音完成后支持本地回放。
- 用户可以提交单句录音进行 AI 点评。
- 后端对临时录音做 ASR，得到识别文本。
- 后端基于原句、识别文本和上下文调用 AI 输出综合评分。
- 点评结果展示总分、发音评分、流利度评分、准确度评分、优点、改进建议、建议练习内容和鼓励语。
- 后端保存识别文本、评分和点评 JSON。
- 后端不长期保存录音文件。
- 支持 Markdown 批量导入脚本，至少可以导入示例资料中的元信息、媒体链接、全文、句子、表达和翻译练习内容。

### 4.2 后续可选

- PC 后台新增、编辑、启用、禁用跟读精听资源。
- 上传视频和音频文件到服务器或对象存储。
- 学习完成度和学习时长统计。
- 句子级学习历史回看。
- 收藏表达和加入单词本。
- 分享学习结果。
- 专业发音评测服务。
- 音素级纠音和波形反馈。
- 自动从网页或第三方源抓取资料。

### 4.3 明确排除

- 不允许游客查看完整学习内容。
- 不保存用户长期录音文件。
- 不把“口语热身”和“跟读精听”作为并列入口。
- 不要求 AI 生成课程内容。
- 不要求 AI 根据资料自动补全缺失字段。
- 不要求在 PC 用户端新增学习页。

## 5. 核心用户流程

### 5.1 用户进入跟读精听列表

- 入口：小程序学习模块中的“跟读精听”。
- 步骤：
  1. 用户打开小程序。
  2. 用户点击“跟读精听”入口。
  3. 小程序进入跟读精听列表页。
  4. 页面默认展示未学习 tab。
  5. 用户可切换到已学习 tab。
- 成功结果：用户看到对应学习状态的资源列表。
- 异常路径：
  - 列表为空：展示空状态文案。
  - 接口失败：展示错误提示和重试按钮。

### 5.2 游客试看详情

- 入口：跟读精听列表页。
- 步骤：
  1. 游客点击任意资源卡片。
  2. 小程序请求详情接口。
  3. 后端识别当前请求无登录身份。
  4. 后端返回试看数据，只包含媒体、简介和基础元信息。
  5. 页面展示视频/音频、标题、简介和登录引导。
- 成功结果：游客可以感知资源内容，但不能学习完整内容。
- 异常路径：
  - 资源不存在：展示“内容不存在”。
  - 媒体播放失败：展示“媒体暂时无法播放，请稍后重试”。

### 5.3 登录用户打开详情并标记已学习

- 入口：跟读精听列表页。
- 步骤：
  1. 登录用户点击资源卡片。
  2. 小程序请求详情接口。
  3. 后端返回完整资源内容。
  4. 后端创建或更新 `user_shadowing_lesson_records`。
  5. 小程序展示完整详情页。
- 成功结果：该资源从未学习列表移动到已学习列表。
- 异常路径：
  - 资源不存在：展示“内容不存在”。
  - 登录态过期：走现有 401 处理并引导登录。
  - 学习记录写入失败：详情仍可展示，但后端应记录错误日志；如果事务要求严格，也可以返回错误并提示重试。

### 5.4 用户完成精听与对照学习

- 入口：跟读精听详情页。
- 步骤：
  1. 用户先观看视频或播放音频。
  2. 用户查看对照原文。
  3. 用户在 `只看英文` 和 `中英对照` 之间切换。
  4. 用户点击高亮表达，可以定位到地道表达区对应卡片。
- 成功结果：用户完成从输入到理解的学习过程。
- 异常路径：
  - 原文为空：隐藏对照原文区。
  - 表达映射失败：点击高亮表达时不跳转，页面不报错。

### 5.5 用户逐句跟读并提交 AI 点评

- 入口：逐句跟读区。
- 步骤：
  1. 用户点击某一句的“播放本句”。
  2. 页面播放该句对应时间段的媒体内容。
  3. 用户点击“录音跟读”。
  4. 小程序调用录音能力并保存本地临时文件。
  5. 用户点击“回放录音”确认效果。
  6. 用户点击“提交点评”。
  7. 后端接收临时录音文件。
  8. 后端调用现有 ASR 能力得到识别文本。
  9. 后端把原句、识别文本、音标、中文翻译、资源标题等上下文传给 AI。
  10. AI 返回 JSON 评分和点评。
  11. 后端保存识别文本、评分和点评 JSON。
  12. 小程序展示点评结果。
- 成功结果：用户获得单句跟读反馈。
- 异常路径：
  - 用户拒绝录音权限：展示授权引导。
  - 录音为空或太短：禁止提交，提示重新录音。
  - ASR 失败：提示“识别失败，请重试”。
  - AI 点评失败：提示“点评暂时不可用，请稍后重试”。
  - AI 返回格式异常：后端兜底为可展示错误，不让页面崩溃。

## 6. 功能需求

### FR-1 首页或学习模块入口替换

- 目标：用“跟读精听”替换现有“口语热身”入口。
- 触发：用户进入首页或学习模块。
- 输入：无。
- 输出：显示“跟读精听”入口。
- 业务规则：
  - 不保留“口语热身”作为并列入口。
  - 入口样式延续小程序现有学习入口视觉。
  - 游客和登录用户都可以点击进入列表页。
- 权限：公开可见。
- 状态：正常、跳转中。

验收标准：

- [ ] 小程序不再展示“口语热身”入口。
- [ ] 小程序展示“跟读精听”入口。
- [ ] 游客点击入口可以进入列表页。
- [ ] 登录用户点击入口可以进入列表页。

### FR-2 跟读精听列表

- 目标：让用户按学习状态浏览资源。
- 触发：进入跟读精听列表页。
- 输入：
  - `learned`：是否已学习。
  - `page`：页码。
  - `size`：每页数量。
- 输出：分页资源列表。
- 业务规则：
  - 默认展示未学习。
  - 登录用户的未学习/已学习由学习记录判断。
  - 游客没有个人学习记录，默认可展示全部资源，tab 可隐藏或只展示全部/试看列表；若保留 tab，则已学习为空。
  - 列表按 `publishedDate` 倒序展示。
- 权限：公开可访问。
- 状态：加载中、空、错误、正常。

验收标准：

- [ ] 列表页默认展示未学习资源。
- [ ] 登录用户可切换未学习和已学习。
- [ ] 资源打开后会从未学习移动到已学习。
- [ ] 游客可以看到资源列表卡片。
- [ ] 空列表展示空状态。
- [ ] 接口失败展示重试按钮。

### FR-3 游客试看详情

- 目标：让游客看到资源价值但不能访问完整学习内容。
- 触发：游客打开资源详情。
- 输入：`lessonId`。
- 输出：试看详情。
- 业务规则：
  - 试看范围仅包含媒体和简介。
  - 不返回完整 `contentJson`。
  - 不返回逐句文本。
  - 不返回重点表达。
  - 不返回中文翻译练习。
  - 不创建学习记录。
- 权限：公开可访问。
- 状态：正常、资源不存在、媒体失败。

验收标准：

- [ ] 游客详情页只展示媒体和简介。
- [ ] 游客看不到完整原文和逐句跟读。
- [ ] 游客点击受限区块时进入登录引导。
- [ ] 游客打开详情不会创建已学习记录。

### FR-4 登录用户完整详情

- 目标：让登录用户完成完整跟读精听学习。
- 触发：登录用户打开资源详情。
- 输入：`lessonId`。
- 输出：完整详情。
- 业务规则：
  - 返回完整 `contentJson`。
  - 创建或更新学习记录。
  - `firstOpenedAt` 只在首次打开时写入。
  - `lastOpenedAt` 每次打开都更新。
- 权限：登录用户。
- 状态：正常、资源不存在、登录过期。

验收标准：

- [ ] 登录用户打开详情后能看到完整内容。
- [ ] 首次打开会创建学习记录。
- [ ] 再次打开会更新最后打开时间。
- [ ] 打开后资源出现在已学习 tab。

### FR-5 媒体播放

- 目标：支持用户看视频或听音频进行输入练习。
- 触发：进入详情页。
- 输入：
  - `videoUrl`
  - `audioUrl`
- 输出：媒体播放器。
- 业务规则：
  - 每份资料都有单独的视频链接和音频链接。
  - 视频和音频独立播放，不从视频中抽取音频。
  - 用户可在视频和音频之间切换。
  - 视频缺失时隐藏视频入口；音频缺失时隐藏音频入口。
- 权限：游客可播放试看媒体；登录用户可播放完整媒体。
- 状态：加载中、播放中、暂停、失败。

验收标准：

- [ ] 视频使用 `videoUrl` 播放。
- [ ] 音频使用 `audioUrl` 播放。
- [ ] 视频和音频可切换。
- [ ] 媒体播放失败时页面仍可阅读简介或文本。

### FR-7 对照原文

- 目标：让用户对照母语者表达排查卡壳点。
- 触发：登录用户进入详情页。
- 输入：
  - 英文全文。
  - 中文全文。
  - 高亮表达。
- 输出：对照原文卡片。
- 业务规则：
  - 支持 `只看英文` 和 `中英对照`。
  - 重点表达应高亮。
  - 点击高亮表达时定位到地道表达区对应卡片。
- 权限：登录用户。
- 状态：正常、内容为空。

验收标准：

- [ ] 可以切换只看英文和中英对照。
- [ ] 重点表达有明显高亮。
- [ ] 点击高亮表达可定位到对应表达，无法定位时不报错。

### FR-8 逐句跟读

- 目标：让用户逐句模仿语音语调并开口练习。
- 触发：登录用户进入逐句跟读区。
- 输入：句子列表。
- 输出：逐句跟读卡片列表。
- 业务规则：
  - 每句展示英文、中文、音标、时间段和高亮表达。
  - 每句提供播放本句、录音跟读、回放录音、提交点评，四个操作在同一行展示。
  - 录音本地临时文件只在当前会话或提交过程中使用。
  - 录音未完成时不能提交点评。
- 权限：登录用户。
- 状态：未录音、录音中、已录音、提交中、点评成功、点评失败。

验收标准：

- [ ] 每句都能展示文本和时间段。
- [ ] 用户可以播放本句。
- [ ] 用户可以录音。
- [ ] 用户可以回放本次录音。
- [ ] 无录音时提交按钮不可用。

### FR-9 AI 综合点评与发音评分

- 目标：基于 ASR 和 AI 给用户句级跟读反馈。
- 触发：用户提交录音点评。
- 输入：
  - 临时录音文件。
  - `lessonId`。
  - `sentenceIndex`。
  - 原句英文。
  - 原句中文。
  - 音标。
- 输出：识别文本、评分和点评。
- 业务规则：
  - 先调用现有 ASR 能力得到 `recognizedText`。
  - 再调用默认 AI 模型进行综合评分。
  - 不接入专业发音评测服务。
  - 不长期保存录音文件。
  - 保存识别文本、评分和点评 JSON。
  - 分数范围为 0-100。
- 权限：登录用户。
- 状态：ASR 中、AI 点评中、成功、失败。

验收标准：

- [ ] 点评结果包含 ASR 识别文本。
- [ ] 点评结果包含总分、发音、流利度、准确度。
- [ ] 点评结果包含优点、改进建议、建议练习内容和鼓励语。
- [ ] 录音文件不会作为长期 URL 保存到数据库。
- [ ] ASR 或 AI 失败时有清晰错误提示。

### FR-10 地道表达

- 目标：让用户学习资料中的重点词汇、短语、句型和表达。
- 触发：登录用户进入详情页。
- 输入：表达列表。
- 输出：表达卡片列表。
- 业务规则：
  - 默认展示表达、音标、类型、释义和原文例句。
  - 点击展开后展示音标、英文解释、中文例句和解析。
  - 表达列表为空时隐藏区块。
- 权限：登录用户。
- 状态：折叠、展开、内容为空。

验收标准：

- [ ] 表达卡片默认信息简洁。
- [ ] 点击后可以展开完整解析。
- [ ] 空表达列表不展示空白区块。

### FR-11 中文翻译练习

- 目标：帮助用户根据中文自己组织英文表达，并通过 AI 点评改进。
- 触发：登录用户进入详情页。
- 输入：
  - 中文提示。
  - 参考英文。
  - 用户英文翻译。
- 输出：翻译练习卡片和 AI 点评结果。
- 业务规则：
  - 默认展示中文提示，不默认展示参考英文。
  - 用户可使用文字输入或语音输入英文翻译。
  - 默认展示可编辑英文输入框。
  - 输入框下方提供“切换为语音输入”按钮；语音输入先通过 ASR 转为可编辑文本并回填输入框。
  - 用户提交后返回 AI 评分、优点、改进建议、纠错和优化翻译。
  - 查看参考英文、AI 点评两个操作按钮同一行展示。
  - 用户可点击查看参考英文。
- 权限：登录用户。
- 状态：未输入、语音识别中、已输入、AI 点评中、点评成功、点评失败、内容为空。

验收标准：

- [ ] 用户能看到中文翻译练习。
- [ ] 用户可以文字输入英文翻译。
- [ ] 用户可以语音输入并识别为可编辑文本。
- [ ] 用户可以提交 AI 点评与改进。
- [ ] 用户能查看参考英文。
- [ ] 内容为空时隐藏该区块。

### FR-12 Markdown 批量导入

- 目标：让开发阶段可以快速导入后续多篇资料。
- 触发：开发者运行导入脚本。
- 输入：Markdown 文件路径。
- 输出：写入或更新 `shadowing_lessons` 数据。
- 业务规则：
  - 支持解析示例资料的结构。
  - 支持导入元信息、标题、栏目、日期、主题、来源、缩略图、视频链接、音频链接。
  - 支持导入精听挑战文本、中英对照、句子列表、表达列表、中文翻译练习。
  - 同一来源 URL 或同一 episode 编号重复导入时，应更新已有记录或提示重复，不能产生不可控重复数据。
  - 解析失败时输出错误原因。
- 权限：仅开发或运维命令使用，不暴露给普通用户。
- 状态：成功、重复、解析失败、数据库失败。

验收标准：

- [ ] 示例 Markdown 能成功导入。
- [ ] 导入后列表页能看到该资源。
- [ ] 详情页能展示导入的媒体、句子和表达。
- [ ] 重复导入不会产生多条同源重复资源。

## 7. 页面与 UI/UX 要求

### 7.1 视觉方向

- 风格：学习工具型，清爽、轻量、适合移动端长内容学习。

- 组件风格：延续现有小程序 iOS / Apple 风格首页视觉，低饱和、轻阴影、圆角卡片。
- 交互语气：鼓励开口，但不使用过长说明文案。
- 内容层级：媒体优先，其次学习步骤，再到表达精讲。

### 7.2 Screen A：跟读精听列表页

- 目的：让用户选择一条待学习或已学习资源。
- 关键内容：
  - 页面标题：`跟读精听`
  - 副标题：`看原声视频，练精听、跟读和地道表达`
  - tab：`未学习`、`已学习`
  - 资源卡片。
- 资源卡片字段：
  - 缩略图。
  - 英文标题。
  - 中文标题。
  - 栏目。
  - 主题标签。
  - 日期。
  - `句子数 · 表达数`。
  - 学习状态。
- 主操作：点击卡片进入详情。
- 次操作：切换 tab、下拉刷新、触底加载更多。
- 空状态：
  - 未学习为空：`暂无新的跟读内容`
  - 已学习为空：`学过的内容会出现在这里`

- 错误状态：`加载失败，点击重试`。
- 响应式：适配微信小程序常见手机屏宽，卡片内容不能溢出。

### 7.3 Screen B：跟读精听详情页

- 目的：承载一次完整的精听、跟读和表达学习。
- 布局：顶部媒体区 + 下方分段学习卡片。
- 区块顺序：
  1. 媒体区。
  2. 简介区。
  3. 对照原文。
  4. 逐句跟读。
  5. 地道表达。
  6. 中文翻译练习。

- 展示视频播放器。
- 提供音频播放器入口或切换。
- 展示标题、中文标题、主题和日期。
- 媒体加载失败时不影响下方内容展示。

#### 游客详情状态

- 展示媒体区和简介。
- 下方展示登录引导卡片：
  - 标题：`登录后解锁完整跟读`

#### 登录用户详情状态

- 展示完整学习区块。
- 每个区块有独立标题和清晰边界。
- 长内容采用折叠或局部展开，避免一屏过载。

### 7.4 可访问性与内容健壮性

- 文字大小遵循现有小程序阅读页面标准。
- 按钮点击区域不小于微信小程序常见触控尺寸。

## 8. 数据模型

### 8.1 Entity：`ShadowingLesson`

表名建议：`shadowing_lessons`

- 描述：跟读精听资源主表。
- 必填字段：
  - `id: BIGINT`
  - `title: VARCHAR(255)` 英文标题或站内标题。
  - `title_zh: VARCHAR(255)` 中文标题。
  - `video_url: VARCHAR(1000)` 视频链接。
  - `audio_url: VARCHAR(1000)` 音频链接。
  - `content_json: JSON or LONGTEXT` 结构化学习内容。
  - `status: VARCHAR(20)` 状态。
  - `created_at: DATETIME`
  - `updated_at: DATETIME`
- 可选字段：
  - `description: TEXT`
  - `episode_no: VARCHAR(50)`
  - `category: VARCHAR(100)`
  - `topic: VARCHAR(100)`
  - `source_name: VARCHAR(100)`
  - `source_url: VARCHAR(1000)`
  - `thumbnail_url: VARCHAR(1000)`
  - `published_date: DATE`
  - `sentence_count: INT`
  - `expression_count: INT`
- 关系：
  - 一个资源可以有多条用户学习记录。
  - 一个资源可以有多条用户点评记录。
- 校验规则：
  - `status` 仅允许 `DRAFT`、`PUBLISHED`、`DISABLED`。
  - 用户端只展示 `PUBLISHED`。
  - `source_url` 或 `episode_no` 建议建立唯一约束或导入脚本层去重。

### 8.2 Entity：`UserShadowingLessonRecord`

表名建议：`user_shadowing_lesson_records`

- 描述：用户是否打开过某条跟读精听资源。
- 必填字段：
  - `id: BIGINT`
  - `user_id: BIGINT`
  - `lesson_id: BIGINT`
  - `first_opened_at: DATETIME`
  - `last_opened_at: DATETIME`
- 关系：
  - 关联 `users.id`。
  - 关联 `shadowing_lessons.id`。
- 校验规则：
  - `user_id + lesson_id` 唯一。
  - 第一次打开写入 `first_opened_at`。
  - 每次打开更新 `last_opened_at`。

### 8.3 Entity：`ShadowingReviewRecord`

表名建议：`shadowing_review_records`

- 描述：用户单句跟读点评结果。
- 必填字段：
  - `id: BIGINT`
  - `user_id: BIGINT`
  - `lesson_id: BIGINT`
  - `sentence_index: INT`
  - `reference_text: TEXT`
  - `recognized_text: TEXT`
  - `overall_score: INT`
  - `pronunciation_score: INT`
  - `fluency_score: INT`
  - `accuracy_score: INT`
  - `feedback_json: JSON or LONGTEXT`
  - `created_at: DATETIME`
- 明确不保存：
  - 不保存长期录音 URL。
  - 不保存永久音频文件路径。
- 校验规则：
  - 分数范围 0-100。
  - `sentence_index` 从 0 或 1 开始必须前后端统一；建议数据库存 0-based，页面展示 1-based。

## 9. API 设计

### 9.1 GET `/api/shadowing-lessons`

- 用途：查询跟读精听列表。
- 权限：公开；登录用户带 token 时返回个人学习状态。
- 查询参数：
  - `learned: boolean` 可选；登录用户有效。
  - `page: int` 默认 0。
  - `size: int` 默认 10。
- 响应：分页对象。

示例响应项：

```json
{
  "id": 1,
  "title": "Episode 1 How to Say Sunny and Dreary Weather",
  "titleZh": "Episode 1 阳光明媚、天气阴沉怎么说？",

  "topic": "天气季节",

  "publishedDate": "2024-08-19",
  "sentenceCount": 6,
  "expressionCount": 10,
  "learned": false
}
```

失败处理：

- 数据库异常：返回 500 和清晰错误信息。
- 未登录请求 `learned=true`：可以返回空列表，也可以忽略 learned 参数；建议返回空列表并保持接口成功。

### 9.3 POST `/api/shadowing-lessons/{id}/sentences/{sentenceIndex}/review`

- 用途：提交单句录音，返回 ASR 和 AI 点评。
- 权限：登录用户。
- 请求类型：`multipart/form-data`。
- 输入：
  - `audioFile`：临时录音文件。
  - `referenceText`：原句英文，可由后端根据 `id` 和 `sentenceIndex` 校验。
  - `durationMs`：录音时长，可选。
- 输出：
  - ASR 识别文本。
  - 总分、发音、流利度、准确度。
  - 结构化点评。

响应示例：

```json
{
  "recognizedText": "I just got out of the shower, I dried my hair.",
  "overallScore": 88,
  "pronunciationScore": 86,
  "fluencyScore": 84,
  "accuracyScore": 94,
  "strengths": [
    "Most key words were recognized correctly.",
    "The sentence meaning is complete."
  ],
  "improvements": [
    "Make the linking in 'out of the' smoother.",
    "Slow down slightly before 'I dried my hair'."
  ],
  "suggestedPractice": [
    "out of the shower",
    "dried my hair"
  ],
  "encouragement": "Good job. Try one more time with smoother linking."
}
```

失败处理：

- 未登录：401。
- 资源不存在：404。
- 句子不存在：400。
- 录音为空：400。
- ASR 失败：502 或 500，并返回“识别失败，请重试”。
- AI 失败：502 或 500，并返回“点评暂时不可用，请稍后重试”。

## 10. AI 点评要求

### 10.1 技术方案

- 使用现有 ASR 能力进行语音转文字。
- 使用现有默认 AI 模型进行综合评分。
- 不接入专业发音评分服务。
- 不做音素级纠音。
- 评分是学习辅助，不应在 UI 中包装成专业考试评分。

### 10.2 AI 输入

- 资源标题。
- 资源中文标题。
- 句子序号。
- 原句英文。
- 原句中文。
- 原句音标。
- ASR 识别文本。
- 录音时长，可选。

### 10.3 AI 输出 JSON

AI 必须返回可解析 JSON：

```json
{
  "overallScore": 88,
  "pronunciationScore": 86,
  "fluencyScore": 84,
  "accuracyScore": 94,
  "strengths": ["..."],
  "improvements": ["..."],
  "suggestedPractice": ["..."],
  "encouragement": "..."
}
```

### 10.4 评分规则建议

- `accuracyScore`：主要参考 ASR 识别文本与原句的相似度。
- `fluencyScore`：参考录音时长、识别文本完整度、AI 对停顿自然度的推断。
- `pronunciationScore`：参考 ASR 可识别程度和关键表达识别情况。
- `overallScore`：综合三个维度，不应简单平均；可以让 AI 根据学习场景给出鼓励型评分。

- AI 调用沿用现有 `AiService` 和默认模型配置。
- ASR 能力优先复用项目已有真实语音转文字能力。
- 文件上传仅用于临时录音处理；不要把临时录音作为长期业务文件保存。
- V1 不引入新的前端框架。

## 13. 非功能需求

### 13.1 性能

- 列表接口应分页返回，默认 `size=10`。
- 详情接口只返回当前资源内容。
- 游客详情不返回完整 `contentJson`，减少数据传输。
- AI 点评可能耗时，前端必须展示提交中状态。

### 13.2 安全

- 点评接口必须要求登录。
- 用户只能提交自己的录音点评。
- 后端不能信任前端传入的 `referenceText`，必须根据 `lessonId` 和 `sentenceIndex` 校验。
- 游客接口不能泄露完整学习内容。

### 13.3 可靠性

- ASR 失败和 AI 失败要分别提示。
- AI JSON 解析失败时需要兜底。
- 媒体播放失败不能影响文本内容浏览。
- 学习记录写入应尽量幂等。

### 13.4 隐私

- 不长期保存录音文件。
- 点评记录只保存文本、分数和结构化反馈。
- 如临时文件落盘，处理完成后应清理。

### 13.5 兼容性

- 适配微信小程序常见 iOS 和 Android 设备。
- 长英文句子、音标和表达标签必须自动换行。

## 15. 实施备注

- 该模块替换“口语热身”，但实现时可以保留旧代码一段时间，确认新入口稳定后再清理。
- 若现有小程序已有 `pages/spokenWarmup` 和 `pages/spokenWarmupDetail`，可以选择复用页面路径但重命名展示文案；也可以新增 `pages/shadowingLessons` 和 `pages/shadowingLessonDetail`，由实现阶段决定。
- 若后端已有真实 ASR 接口，点评接口应复用；若没有，需要先补齐“临时音频 -> ASR 文本”的能力。
- 导入脚本建议先支持单文件导入，再扩展目录批量导入。

## 16. Assumptions

- 小程序端仍通过 REST API 直连 Spring Boot 后端。
- 游客可以播放试看媒体，但不能获取完整 `contentJson`。
- 点开详情即已学习，该规则 V1 固定，不要求用户看完、录完或点击完成。
- 示例资料中的视频和音频链接后续会稳定可访问。
- 后续提供的资料 Markdown 结构与示例文件基本一致。
- AI 综合评分用于学习反馈，不作为专业发音认证结果。

## 17. Open Questions

- 游客试看媒体是否允许播放完整视频/音频，还是只允许播放前若干秒。当前已确认“只展示媒体和简介”，但未限制媒体播放时长。
- 跟读点评历史是否需要在详情页展示最近一次结果。当前建议保存记录，但 V1 页面可只展示本次提交结果。
- 录音临时文件具体保留多久由实现阶段根据服务器文件处理方案确定，原则是不长期保存业务录音。
