## C. 后端接口扩展（微信登录）

> 小程序前端直接复用现有 Java 后端接口，仅需后端配合新增微信登录接口。

### C1. 新增微信登录接口
**类型**：后端（Java）

任务：
1. 新增 `POST /api/auth/wechat-login` 接口
2. 接收小程序前端传来的微信临时登录凭证 `code`
3. 调用微信接口换取 `openid`
4. 查询 `user_wechat_auth` 表是否已绑定用户
5. 若已绑定，直接签发 token 登录
6. 若未绑定，自动创建用户 + 绑定关系 + 赠送 3 天会员，再签发 token
7. 返回与现有登录接口一致的响应格式：`{ token, username, role }`

### C2. 新增 user_wechat_auth 表
**类型**：后端（Java）

任务：
1. 新增 `user_wechat_auth` 表，字段：`id`、`user_id`、`wechat_open_id`、`wechat_union_id`、`created_at`、`updated_at`
2. `wechat_open_id` 唯一约束
3. `user_id` 外键关联 `users.id`

### C3. 确认卡密兑换与会员状态接口
**类型**：后端（Java）

任务：
1. 确认卡密兑换接口是否已对普通用户开放，如未开放则新增
2. 确认会员状态查询接口是否存在，如未实现则新增 `GET /api/user/membership`

## 8. 风险与处理建议

### 风险 1：前端页面风格不统一
建议：先沉淀组件库和设计规范，再开发页面。

### 风险 2：微信登录接口联调问题
建议：提前确认微信小程序 AppID 和后端微信 API 配置。

### 风险 3：AI 返回数据不稳定
建议：前端做好异常兜底展示。

## 9. 结论

本版任务拆解调整为：

1. 小程序前端统一设计系统优先。
2. 小程序前端直接对接现有 Java 后端接口。
3. 后端仅需配合新增微信登录接口，其余接口直接复用。

这样最大化复用现有后端能力，降低建设成本。
