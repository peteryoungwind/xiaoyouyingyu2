# 小柚英语微信小程序软件需求规格说明书（SRS）

> 版本：1.1
> 日期：2026-04-02
> 项目：小柚英语微信小程序
> 本版调整重点：
> 1. 前端页面风格统一
> 2. 小程序配套独立后端实现全部业务
> 3. 独立后端继续使用现有 MySQL 表结构与历史数据
> 4. 新增微信号一键登录，未注册用户自动注册

---

## 1. 引言

### 1.1 编写目的

本文档定义小柚英语微信小程序的正式软件需求，供产品、设计、前后端开发、测试与部署使用。本文档重点明确：

1. 系统目标与范围
2. 角色、规则与约束
3. 功能性需求
4. 页面与接口要求
5. 数据兼容要求
6. 非功能要求
7. 验收标准

### 1.2 项目背景

当前小柚英语已具备一套 Web 系统与既有 MySQL 数据资产。微信小程序版本不再依赖现有 Java 服务，而要建设：

- 独立小程序前端
- 独立小程序后端
- 继续连接现有 MySQL 数据库
- 兼容既有表结构与历史数据

### 1.3 术语定义

- **主题 / Topic**：英语口语练习主题。
- **学习中心**：围绕主题生成并组织练习内容的模块。
- **会员**：具有学习中心权限的用户状态。
- **卡密**：可兑换会员时长的唯一兑换码。
- **独立后端**：指不依赖当前 Java 服务、单独部署的小程序业务服务。
- **账号合并**：指用户名密码账号与微信账号最终归并到同一个 `users` 用户主体下。
- **微信绑定表**：建议新增 `user_wechat_auth`，用于维护微信身份与系统用户的绑定关系。

## 2. 总体描述

### 2.1 产品目标

小程序系统应满足以下目标：

1. 为用户提供移动端英语口语练习入口。
2. 提供统一且一致的页面视觉与交互体验。
3. 通过独立后端完整承接主题、学习、会员、卡密等业务。
4. 保持对现有 MySQL 数据结构的兼容，复用现有数据资产。

### 2.2 产品范围

#### 一期范围
- 微信号一键注册/登录
- 用户注册/登录
- 首页
- 主题列表与详情
- 学习中心首页与主题学习页
- 会员状态展示
- 卡密兑换
- 设置页与个人中心
- 日历页
- 会员开通引导
- 独立后端搭建
- MySQL 数据兼容接入

#### 非一期范围
- 小程序完整运营后台
- 在线支付会员
- 录音作答
- 学习记录完整沉淀
- 成就系统

### 2.3 用户角色

#### 游客
- 可浏览公开内容
- 不可搜索
- 不可进入学习中心

#### 普通用户 USER
- 可通过用户名密码登录/注册
- 可通过微信号一键登录
- 可搜索主题
- 可查看完整主题详情
- 可查看会员状态
- 可兑换卡密
- 默认不可访问学习中心

#### 会员用户
- 可访问学习中心与 AI 练习能力
- 会员身份由 `membership_expire_at` 判定

#### 管理员 ADMIN
- 拥有全部用户权限
- 后续可扩展管理功能

### 2.4 设计约束

1. 小程序前端必须形成统一 UI 风格。
2. 小程序后端必须独立实现全部业务，不依赖 Java 服务。
3. 独立后端必须兼容现有 MySQL 表结构。
4. 后端权限校验必须独立实现。

## 4. 业务规则

### 4.1 会员判定规则

1. `ADMIN` 始终拥有高级权限。
2. 非管理员用户，当 `membership_expire_at > 当前时间` 时视为会员有效。
3. 会员过期后自动失去学习中心权限。
4. 历史 `PREMIUM_USER` 数据需要兼容，但权限口径以有效期为准。

### 4.2 注册赠送规则

1. 用户名密码注册成功后赠送 3 天会员。
2. 微信号一键登录且判定为首次注册的用户，也应自动完成注册并赠送 3 天会员。
3. 注册返回中应包含会员状态。

### 4.3 微信号一键登录规则

1. 小程序前端通过微信登录能力获取临时登录凭证。
2. 小程序后端通过微信接口换取用户身份标识。
3. 若该微信身份已绑定系统用户，则直接登录。
4. 若该微信身份未绑定用户，则自动创建新用户并登录。
5. 自动注册用户需写入用户表，并建立微信身份关联。
6. 自动注册过程必须保证用户唯一性与事务一致性。

### 4.4 用户名密码账号与微信账号合并规则

1. 平台以 `users` 作为唯一用户主体。
2. 用户名密码登录与微信登录属于同一用户的不同登录方式。
3. 推荐新增 `user_wechat_auth` 绑定表维护微信身份关系。
4. 微信首次登录且无绑定关系时：
   - 创建一条新的 `users` 记录
   - 创建对应的 `user_wechat_auth` 绑定记录
   - 完成自动注册与登录
5. 微信再次登录时，通过 `user_wechat_auth` 直接找到已有用户并登录。
6. 已有用户名密码账号的用户，应支持显式“绑定微信”。
7. 已有微信自动注册账号的用户，应支持补设用户名和密码。
8. 不允许根据昵称、用户名相似等弱条件自动合并账号。
9. 同一个微信身份只能绑定一个用户。

### 4.5 卡密兑换规则

1. 卡密必须存在且未使用。
2. 卡密不能被禁用或过期。
3. 会员有效时，兑换时间从当前到期时间继续累加。
4. 会员无效时，兑换时间从当前时间开始累加。

### 4.4 学习中心访问规则

1. 游客不可访问学习中心。
2. 普通用户不可访问学习中心。
3. 会员用户与管理员可访问学习中心。
4. 访问被拒绝时必须返回明确可识别的错误状态。

## 5. 功能需求

## 5.1 认证与用户

### FR-001 用户注册
系统应支持用户名密码注册，并在注册后自动赠送 3 天会员。

### FR-002 用户名密码登录
系统应支持用户名密码登录，并返回 token 与会员状态。

### FR-003 微信号一键登录
系统应支持微信号一键登录。

规则：
1. 已注册微信用户直接登录。
2. 未注册微信用户自动注册并登录。
3. 自动注册成功后应赠送 3 天会员。
4. 登录返回中应包含 token、用户身份与会员状态。

### FR-004 账号绑定与补全
系统应支持以下账号合并能力：
1. 已有用户名密码账号的用户，可主动绑定微信。
2. 已通过微信自动注册的用户，可补设用户名和密码。
3. 若目标微信身份已绑定其他用户，绑定操作必须拒绝。
4. 绑定成功后，两种登录方式都应归属于同一个 `users.id`。

### FR-005 修改密码
系统应支持已登录用户修改密码。

### FR-006 获取当前用户会员信息
系统应支持查询当前用户会员状态，包括：
- role
- membershipActive
- membershipExpireAt
- remainingDays
- membershipSource
- isAdmin

## 6. 独立后端需求

## 6.1 后端总体要求

### BR-API-001 独立实现要求
小程序后端必须独立实现以下业务能力：
- 账号体系
- 用户名密码登录与注册
- 微信号一键登录与自动注册
- 鉴权体系
- 主题查询体系
- 学习中心体系
- 会员体系
- 卡密体系
- AI 调用体系

### BR-API-002 不依赖 Java 服务
新后端不得将当前 Java 服务作为业务运行时依赖。

### BR-API-003 可独立部署
新后端应支持独立部署、独立配置、独立日志与监控。

---

## 6.2 数据兼容需求

### DR-001 数据库继续使用 MySQL
新后端必须继续使用现有 MySQL 数据库。

### DR-002 表结构兼容
必须兼容以下现有表：
- `users`
- `topics`
- `ai_models`
- `redeem_codes`
- `membership_records`

同时为账号合并与微信登录，推荐新增：
- `user_wechat_auth`

建议字段：
- `id`
- `user_id`
- `wechat_open_id`
- `wechat_union_id`
- `created_at`
- `updated_at`

规则：
1. `user_id` 指向唯一用户主体 `users.id`
2. `wechat_open_id` 应唯一
3. 若存在 `wechat_union_id`，也建议唯一约束
4. 同一微信身份不得绑定多个用户

### DR-003 历史数据兼容
必须兼容现有历史数据，包括：
- 历史用户
- 历史主题
- 历史会员状态
- 历史卡密
- 历史会员流水

### DR-004 字段语义兼容
不得擅自改变既有字段语义，例如：
- `membership_expire_at`
- `role`
- `questions`
- `status`
- `used_by`

### DR-005 新增表要求
如果后续新增练习记录等表，必须：
1. 保持命名规范统一
2. 与现有用户、主题主键逻辑兼容
3. 不破坏现有业务数据读取

## 8. 非功能需求

### 8.1 性能
1. 主题列表分页请求应稳定。
2. AI 生成需返回明确 loading 过程控制信号。
3. 首页、主题列表首屏加载需较快。

### 8.2 安全
1. 密码必须加密存储。
2. 鉴权令牌必须安全签发与校验。
3. 卡密兑换必须事务控制。
4. 敏感配置必须环境变量化。

### 8.3 可维护性
1. 前端组件统一、可复用。
2. 后端模块分层清晰。
3. 数据访问层需单独封装 MySQL 适配逻辑。
4. AI 调用逻辑需单独封装。

### 8.4 一致性
1. 前端所有页面风格一致。
2. 前端所有受限态、空状态、错误态风格一致。
3. 前后端关于会员状态的口径一致。
4. 新后端与现有 MySQL 字段语义保持一致。

## 9. 验收标准

### 9.1 前端一致性验收
- 首页、主题页、学习页、我的页视觉风格统一。
- 卡片、按钮、输入框、弹窗样式统一。
- 空状态、受限状态、加载状态一致。

### 9.2 独立后端验收
- 小程序后端在 Java 服务不可用时仍能独立运行。
- 登录、主题、学习、会员、卡密功能均由新后端完成。

### 9.3 MySQL 兼容验收
- 新后端能正确读取现有 `users`、`topics`、`redeem_codes`、`membership_records` 等表。
- 历史数据可正常使用。
- 不出现字段语义错配。

### 9.4 业务验收
- 新用户注册后自动获得 3 天会员。
- 登录用户可搜索主题。
- 会员用户可进入学习中心并获取 AI 点评。
- 非会员用户被统一引导开通。
- 有效卡密可正常兑换。

---

## 10. 结论

本版 SRS 明确了小柚英语微信小程序的关键建设方向：

1. 前端风格统一。
2. 后端独立实现。
3. 数据继续复用现有 MySQL。

该方案适合在现有业务已验证的基础上，建设一套更适合小程序长期演进的独立系统。
