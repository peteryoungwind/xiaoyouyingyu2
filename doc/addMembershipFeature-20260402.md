下面我把“高级用户会员功能”整理成一份可直接进入设计和开发阶段的需求文档。它会基于你当前已经实现的用户系统、权限体系、学习中心权限控制和后台用户管理能力继续往下扩展。

**一、功能目标**

当前系统已经具备：

- 用户注册 / 登录
- 普通用户、管理员、高级用户三种角色
- 学习中心仅高级用户和管理员可访问
- 管理员可在用户管理页直接修改用户角色

这次新增会员体系的目标，不再只是“手动改角色”，而是把高级用户升级为一套 `有有效期、可兑换、可自动失效、可后台管理` 的正式会员机制。

本次要实现的核心能力：

1. 普通用户可通过 `卡密兑换` 成为高级用户
2. 高级用户有 `会员有效期`
3. 会员到期后系统自动将用户降级为普通用户
4. 支持用户发起 `会员购买或续费`
5. 管理员可生成卡密，并设置卡密对应的会员时长或截止时间
6. 管理员可手动为指定用户设置会员有效期
7. 新注册用户默认赠送 `3 天会员`

---

**二、适用角色**

### 1. 普通用户 `USER`

- 可注册、登录、浏览普通内容
- 可查看自己的会员状态
- 可使用卡密兑换会员
- 可发起会员购买或续费
- 会员有效期内，可访问高级用户功能

### 2. 高级用户 `PREMIUM_USER`

- 拥有普通用户全部权限
- 可访问学习中心全部功能
- 其高级身份由 `会员有效期` 驱动，而不是单纯手工改角色

### 3. 管理员 `ADMIN`

- 可生成卡密
- 可查看卡密使用情况
- 可手动为用户设置会员到期时间
- 可查看用户会员状态和剩余时间
- 管理员本身始终拥有高级权限，不受会员有效期限制

**三、核心业务规则**

### 1. 会员身份判定规则

系统需要把“用户角色”和“会员有效期”结合起来判断权限：

- `ADMIN`：永远拥有管理员及高级权限
- `USER`：
  - 当会员有效期为空，或已过期时，为普通用户
  - 当会员有效期晚于当前时间时，自动视为高级用户
- `PREMIUM_USER`：
  - 兼容旧数据，但后续应逐步统一为“通过有效期驱动高级状态”

更推荐的落地方向是：

- 保留 `role` 字段用于区分 `ADMIN` 和普通用户
- 新增 `membership_expire_at`
- 非管理员用户是否属于高级用户，由 `membership_expire_at > 当前时间` 动态判断

这样可以避免“角色是高级用户但会员其实已经过期”的脏数据问题。

### 1.1 会员购买与续费规则

除了卡密兑换外，系统还需要支持 `会员购买` 和 `会员续费` 的业务入口。

结合你当前的业务阶段，第一期建议采用 `人工开通 / 人工续费` 方案：

- 用户点击购买会员或续费会员
- 系统统一弹窗提示：`请联系管理员开通高级功能`
- 管理员可通过后台手动设置会员有效期，或发放卡密给用户兑换

这样做的好处是：

- 先把业务流程跑通
- 不需要立即接入支付系统
- 后续若接在线支付，可复用现有会员到期时间模型

因此本次文档里，“购买”和“续费”统一定义为：

- `购买会员`：首次开通或已过期后重新开通会员
- `续费会员`：在当前会员未过期或已过期的情况下继续延长会员时间

### 2. 新用户赠送规则

- 新用户注册成功后，系统自动赠送 `3 天会员`
- 赠送起点为注册成功时间
- 到期时间 = 注册时间 + 3 天
- 注册后用户可立即访问高级用户功能

例如：
- 用户在 `2026-04-02 10:00:00` 注册
- 默认会员到期时间为 `2026-04-05 10:00:00`

### 3. 卡密兑换规则

- 用户输入合法且未使用的卡密后，系统完成兑换
- 兑换成功后，系统为该用户增加会员时长或更新会员到期时间
- 每个卡密只能使用一次
- 已使用、已过期、已禁用的卡密不可再次兑换

建议采用 `叠加时长` 规则，用户体验更好：

- 如果用户当前不是会员，或会员已过期：
  新到期时间 = 当前时间 + 卡密时长
- 如果用户当前仍是会员：
  新到期时间 = 当前会员到期时间 + 卡密时长

例如：
- 当前会员到期时间为 `2026-04-10 00:00:00`
- 兑换一张 `30 天卡`
- 新到期时间变为 `2026-05-10 00:00:00`

### 4. 管理员手动设置规则

管理员可在后台直接为用户设置会员到期时间，支持两种操作：

- `直接设置截止时间`
- `在当前基础上追加天数`

建议两种都支持，因为适用场景不同：

- 直接设置截止时间：适合客服补偿、纠错、统一调整
- 追加天数：适合活动赠送、续期

### 5. 自动降级规则

- 当非管理员用户的会员到期时间小于等于当前时间时
- 系统应自动视其失去高级用户资格
- 用户再次访问高级功能时，应被拦截并提示会员已到期

这里建议采用 `动态判定 + 定时兜底` 双机制：

- `动态判定`
  每次鉴权或查询用户信息时，实时根据 `membership_expire_at` 判断是否是会员
- `定时兜底`
  可增加定时任务，每小时或每天扫描一次已过期用户，把兼容字段同步修正

这样即使定时任务未执行，权限判断也不会出错。

**四、功能范围**

### 1. 用户端功能

#### 1.1 会员状态展示

用户在前端应能看到自己的会员信息，建议展示：

- 当前身份：普通用户 / 高级用户 / 管理员
- 会员是否有效
- 会员到期时间
- 剩余天数
- 若已过期，显示“会员已过期”
- 提供“购买会员 / 续费会员”入口

建议展示位置：

- 顶部导航栏用户信息区域
- 设置页
- 学习中心受限页的提示区域

#### 1.2 卡密兑换页面

新增 `卡密兑换` 功能页或弹窗。

建议交互：

- 输入卡密
- 点击兑换
- 返回兑换结果
- 成功后刷新会员状态

成功提示建议包含：

- 卡密名称或类型
- 增加的会员时长
- 最新到期时间

失败提示建议区分原因：

- 卡密不存在
- 卡密已被使用
- 卡密已过期
- 卡密已禁用
- 当前登录状态失效

#### 1.3 购买会员 / 续费会员入口

用户端应增加 `购买会员` 和 `续费会员` 入口。

建议入口位置：

- 顶部用户菜单
- 设置页会员信息卡片
- 学习中心受限提示区域

点击入口后，第一期统一弹窗提示：

`请联系管理员开通高级功能`

弹窗建议内容：

- 主标题：请联系管理员开通高级功能
- 辅助说明：如“开通或续费后即可继续使用学习中心等高级功能”
- 管理员联系方式展示区域
- 可选按钮：`兑换卡密`、`关闭`

管理员联系方式建议支持后续配置化，可展示：

- 微信号
- 手机号
- 二维码图片
- 客服说明

#### 1.4 会员拦截与引导

当普通用户访问学习中心等高级功能时：

- 仍然拦截访问
- 不只是静态提示
- 应直接弹窗提示：`请联系管理员开通高级功能`

建议细分提示文案：

- 未开通会员用户：`请联系管理员开通高级功能`
- 会员已过期用户：`你的高级会员已过期，请联系管理员开通高级功能`

弹窗中可选附加操作：

- 兑换卡密
- 联系管理员
- 关闭

### 2. 管理端功能

#### 2.1 卡密管理

后台新增 `卡密管理` 页面，建议支持：

- 查看卡密列表
- 按状态筛选：未使用 / 已使用 / 已过期 / 已禁用
- 按创建时间筛选
- 按使用人筛选
- 生成单个卡密
- 批量生成卡密
- 禁用卡密
- 查看卡密详情

卡密列表建议展示字段：

- 卡密码
- 卡密名称
- 会员时长
- 卡密有效期
- 状态
- 是否已使用
- 使用人
- 使用时间
- 创建人
- 创建时间

#### 2.2 生成卡密

管理员生成卡密时建议填写：

- 卡密名称
- 卡密数量
- 会员时长（如 7 天 / 30 天 / 90 天）
- 卡密本身的截止使用时间
- 备注

生成规则建议：

- 卡密码由系统自动生成
- 默认唯一，不可重复
- 支持批量生成
- 支持复制导出

卡密使用中要区分两个“有效期”：

- `会员时长`
  用户兑换成功后可获得多少天会员
- `卡密截止时间`
  这张卡密最晚什么时候之前必须被兑换

例如：
- 一张 `30 天会员卡`
- 卡密截止兑换时间为 `2026-06-30 23:59:59`
- 用户在截止前兑换，则获得 `30 天会员`

#### 2.3 手动设置用户会员

在现有用户管理页面中，为每个用户增加会员管理能力。

建议支持操作：

- 查看当前会员到期时间
- 直接修改会员到期时间
- 追加会员天数
- 清空会员有效期

建议增加操作日志，记录：

- 操作管理员
- 被操作用户
- 变更前到期时间
- 变更后到期时间
- 操作原因
- 操作时间

#### 2.4 用户列表增加会员字段

用户管理页建议新增展示：

- 当前会员状态
- 会员到期时间
- 剩余天数
- 是否为赠送会员 / 卡密兑换 / 管理员手动设置

#### 2.5 购买 / 续费的后台承接方式

由于第一期采用“联系管理员开通”的方式，管理员后台要能承接购买和续费场景。

建议后台支持以下处理方式：

- 首次开通会员：直接设置会员到期时间
- 会员续费：追加会员天数
- 发放卡密：让用户自行兑换

也就是说：

- `购买会员` 最终对应管理员为用户开通会员
- `续费会员` 最终对应管理员延长用户会员有效期

**五、详细业务流程**

### 1. 新用户注册赠送会员流程

1. 用户提交注册信息
2. 系统创建用户账号
3. 系统自动写入会员到期时间 = 注册时间 + 3 天
4. 返回登录态及用户信息
5. 前端显示该用户为高级用户，可立即进入学习中心

### 2. 用户卡密兑换流程

1. 用户进入卡密兑换页
2. 输入卡密并提交
3. 后端校验卡密是否存在、是否可用、是否过期、是否已使用
4. 后端计算新的会员到期时间
5. 标记卡密已使用，并记录使用人和使用时间
6. 更新用户会员到期时间
7. 返回兑换成功结果和最新会员信息

### 3. 用户购买 / 续费咨询流程

1. 用户点击购买会员或续费会员入口
2. 系统弹窗提示：`请联系管理员开通高级功能`
3. 用户联系管理员
4. 管理员后台手动设置会员截止时间，或向用户发放卡密
5. 用户刷新页面后获得最新会员状态

### 4. 会员到期降级流程

1. 用户访问需要高级权限的功能
2. 系统判断当前用户是否管理员
3. 若不是管理员，则检查会员到期时间
4. 若会员已过期，则拒绝访问高级功能
5. 前端统一弹窗提示：`请联系管理员开通高级功能`
6. 如有需要，弹窗中可附带兑换卡密入口

### 5. 管理员手动设置会员流程

1. 管理员进入用户管理页
2. 打开某个用户的会员设置操作
3. 选择“直接设置到期时间”或“追加天数”
4. 提交后端保存
5. 用户会员状态即时生效

### 6. 管理员生成卡密流程

1. 管理员进入卡密管理页
2. 填写卡密参数
3. 系统生成卡密
4. 卡密进入列表，可复制、导出、分发

**六、数据结构建议**

### 1. users 表扩展

建议在 `users` 表新增以下字段：

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `membership_expire_at` | DATETIME | 可空 | 会员到期时间 |
| `membership_source` | VARCHAR(30) | 可空 | 最近一次会员来源：`REGISTER_GIFT` / `REDEEM_CODE` / `ADMIN_GRANT` |
| `membership_updated_at` | DATETIME | 可空 | 最近一次会员更新时间 |

说明：

- `membership_expire_at` 是核心字段
- `membership_source` 用于前后台展示最近一次会员来源
- 如后续要做完整会员流水，不能只靠这个字段，还需要单独日志表

### 2. redeem_codes 表

建议新增 `redeem_codes` 表管理卡密。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK, AUTO_INCREMENT | 主键 |
| `code` | VARCHAR(64) | UNIQUE, NOT NULL | 卡密码 |
| `name` | VARCHAR(100) | 可空 | 卡密名称 |
| `days` | INT | NOT NULL | 兑换后增加的会员天数 |
| `expire_at` | DATETIME | 可空 | 卡密截止兑换时间 |
| `status` | VARCHAR(20) | NOT NULL | `ACTIVE` / `USED` / `DISABLED` / `EXPIRED` |
| `used_by` | BIGINT | 可空 | 使用者用户 ID |
| `used_at` | DATETIME | 可空 | 使用时间 |
| `remark` | VARCHAR(255) | 可空 | 备注 |
| `created_by` | BIGINT | 可空 | 创建管理员 ID |
| `created_at` | DATETIME | NOT NULL | 创建时间 |

说明：

- `days` 表示会员时长，单位建议统一为天
- `status=EXPIRED` 可由查询逻辑动态得出，也可由定时任务回写

### 3. membership_records 表

建议新增会员变更流水表，便于后续追踪和审计。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PK, AUTO_INCREMENT | 主键 |
| `user_id` | BIGINT | NOT NULL | 用户 ID |
| `change_type` | VARCHAR(30) | NOT NULL | `REGISTER_GIFT` / `REDEEM_CODE` / `ADMIN_SET` / `ADMIN_ADD` / `EXPIRE` |
| `days` | INT | 可空 | 增减天数 |
| `before_expire_at` | DATETIME | 可空 | 变更前到期时间 |
| `after_expire_at` | DATETIME | 可空 | 变更后到期时间 |
| `related_code_id` | BIGINT | 可空 | 关联卡密 ID |
| `operator_id` | BIGINT | 可空 | 操作人（管理员） |
| `remark` | VARCHAR(255) | 可空 | 备注 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |

这个表不是 MVP 必须，但非常建议第一期就建。

**七、接口需求建议**

### 1. 用户端接口

#### 1.1 获取当前用户会员信息

`GET /api/user/membership`

返回建议：

- 用户角色
- 是否为会员
- 会员到期时间
- 剩余秒数或剩余天数
- 最近会员来源

#### 1.2 获取会员开通联系信息

`GET /api/user/membership-contact`

用于获取弹窗中展示的管理员联系信息。

返回建议：

```json
{
  "message": "请联系管理员开通高级功能",
  "contactName": "管理员",
  "wechat": "915981048",
  "phone": "",
  "qrCodeUrl": ""
}
```

#### 1.3 卡密兑换

`POST /api/redeem-codes/redeem`

请求参数：

```json
{
  "code": "ABCDEF123456"
}
```

返回建议：

```json
{
  "success": true,
  "message": "兑换成功",
  "daysAdded": 30,
  "membershipExpireAt": "2026-05-10T00:00:00",
  "membershipActive": true
}
```

### 2. 管理端接口

#### 2.1 生成卡密

`POST /api/admin/redeem-codes`

支持单个或批量生成。

请求参数建议：

```json
{
  "name": "4月活动30天卡",
  "count": 20,
  "days": 30,
  "expireAt": "2026-06-30T23:59:59",
  "remark": "英语角线下活动发放"
}
```

#### 2.2 查询卡密列表

`GET /api/admin/redeem-codes`

支持分页和筛选：

- status
- usedBy
- createdAtStart
- createdAtEnd

#### 2.3 禁用卡密

`PATCH /api/admin/redeem-codes/{id}/disable`

#### 2.4 设置用户会员截止时间

`PATCH /api/admin/users/{id}/membership-expire-at`

请求参数建议：

```json
{
  "expireAt": "2026-07-01T00:00:00",
  "remark": "客服补偿"
}
```

#### 2.5 给用户追加会员天数

`POST /api/admin/users/{id}/membership-add-days`

请求参数建议：

```json
{
  "days": 30,
  "remark": "活动赠送"
}
```

#### 2.6 查询用户会员变更记录

`GET /api/admin/users/{id}/membership-records`

#### 2.7 配置会员联系管理员信息

`PUT /api/admin/system/membership-contact`

用于维护“请联系管理员开通高级功能”弹窗中的联系方式内容。

**九、权限与鉴权调整**

### 1. 后端权限判断

当前系统中学习中心权限是通过角色 `PREMIUM_USER` / `ADMIN` 控制。

新增会员体系后，建议升级为：

- `ADMIN`：直接放行
- 非管理员用户：
  - 若会员未过期，允许访问高级功能
  - 若会员已过期，不允许访问

也就是说，权限判断要从“只看 role”升级为“看 role + membership_expire_at”。

对于前端交互，还需要增加一层统一拦截：

- 用户点击高级功能但无权限时
- 统一弹窗：`请联系管理员开通高级功能`

### 2. JWT 与前端用户信息

建议登录、注册、获取当前用户信息时，返回更多会员字段：

- `role`
- `membershipExpireAt`
- `membershipActive`
- `isAdmin`
- `isPremium`

这样前端就可以更准确展示状态，而不需要只靠 `role === PREMIUM_USER` 判断。

**十、状态定义建议**

### 1. 用户会员状态

建议统一成以下展示状态：

- `ADMIN`
- `PREMIUM_ACTIVE`
- `USER_ACTIVE_GIFT`
- `USER_EXPIRED`
- `USER_NEVER_OPENED`

如果前期觉得太复杂，前端展示层至少要能区分：

- 管理员
- 会员中
- 已过期
- 普通用户

### 2. 卡密状态

- `ACTIVE`：可使用
- `USED`：已被兑换
- `DISABLED`：管理员手动禁用
- `EXPIRED`：超过截止兑换时间

**十一、边界情况与异常处理**

### 1. 用户重复兑换多张卡

- 允许
- 会员时间按规则叠加

### 2. 用户会员已过期后兑换

- 从当前时间开始重新计算

### 3. 卡密在提交瞬间被其他人使用

- 后端必须做事务控制
- 只能有一人兑换成功

### 4. 管理员把用户会员时间改短或清空

- 变更后立即生效
- 用户下次访问高级功能时按新状态判断

### 5. 卡密过期但状态字段未及时更新

- 以后端实时校验 `expire_at` 为准
- 状态字段仅作为展示或缓存

### 6. 历史老用户数据兼容

如果当前系统中已经存在 `PREMIUM_USER` 但没有会员到期时间的用户，建议迁移策略：

- 管理员账号：忽略会员到期时间
- 普通高级用户：
  - 可先统一补一个默认到期时间
  - 或标记为长期会员，再由后台逐步人工整理

这个迁移策略需要上线前单独确认。

### 7. 用户点击高级功能但无权限

- 不论入口来自首页、学习中心入口还是深层页面
- 只要当前用户无高级权限，就统一弹窗：
  `请联系管理员开通高级功能`

这样交互更统一，也更符合当前“人工开通会员”的业务阶段。

**十三、验收标准**

### 1. 注册赠送

- 新用户注册成功后自动获得 3 天会员
- 注册后立即可访问学习中心

### 2. 卡密兑换

- 用户可成功兑换有效卡密
- 兑换后会员到期时间正确更新
- 已使用卡密不可再次兑换
- 已过期卡密不可兑换

### 3. 自动降级

- 用户会员过期后不可访问学习中心
- 用户点击高级功能时会弹出“请联系管理员开通高级功能”

### 4. 管理后台

- 管理员可生成卡密
- 管理员可查看卡密状态
- 管理员可手动设置用户会员到期时间
- 管理员可给用户追加会员天数

### 5. 购买与续费引导

- 普通用户点击购买会员时，会弹出“请联系管理员开通高级功能”
- 已过期会员点击高级功能时，会弹出“请联系管理员开通高级功能”
- 用户端可以看到购买会员或续费会员入口

### 5. 状态一致性

- 用户端展示的会员状态与后端权限判断一致
- 管理后台展示的到期时间与实际权限一致
