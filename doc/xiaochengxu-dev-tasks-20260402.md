1. 小程序前端任务
2. 小程序独立后端任务

5. 上线准备任务

## 2. 一期目标

### 核心目标
完成一套：
- 前端风格统一
- 后端独立可运行
- 数据兼容现有 MySQL
- 覆盖主题、学习、会员、卡密主链路

### 一期完成标志
1. 小程序前端形成统一 UI 规范。
2. 小程序后端可脱离 Java 服务独立运行。
3. 新后端可直接读写现有 MySQL 主要表。
4. 用户可完成用户名密码注册、登录、浏览、学习、卡密兑换。
5. 用户可使用微信号一键登录，未注册用户会自动注册并完成登录。

这是本次新增的重点任务。

**类型**：后端/DBA

任务：
1. 输出 `users` 表字段映射
2. 输出 `topics` 表字段映射
3. 输出 `ai_models` 表字段映射
4. 输出 `redeem_codes` 表字段映射
5. 输出 `membership_records` 表字段映射
6. 输出新增 `user_wechat_auth` 表设计
7. 明确 `user_wechat_auth` 与 `users.id` 的绑定关系

### E2. 建立数据模型映射层
**类型**：后端

1. 为现有表建立实体/模型映射
2. 处理字段命名差异

## 8. 风险与处理建议

### 风险 1：前端页面风格不统一
建议：先沉淀组件库和设计规范，再开发页面。

### 风险 2：新后端与旧 MySQL 字段含义理解不一致
建议：先输出字段映射文档，再开发业务逻辑。

### 风险 3：独立后端上线后与旧系统并行产生数据冲突
建议：统一会员判定、卡密状态和流水记录口径。

### 风险 4：AI 返回数据不稳定
建议：后端统一清洗和约束 AI 输出。

## 9. 结论

本版任务拆解已从“复用 Java 后端”调整为：

1. 小程序前端统一设计系统优先。
2. 小程序独立后端完整开发。
3. 现有 MySQL 表结构兼容接入作为核心前置任务。

这样更适合小程序形成完整独立系统，并延续现有数据资产。
